# Changelog

All notable changes to nen. Versions are git tags on `main`; a tag is not a release — see [Install](README.md#install).

## Unreleased

### Added

- **shu** — `nen shu test-report` runs the lane's declared **`test`** command and parses the results it produced into one shape: a row per test (`name`, `suite`, `status`, `durationMs`) and the four counts, under `nen.shu.test-report/v0.1`. It declares nothing of its own — it runs `project.verbs.<lane>.test` and reads *that* row's `artifacts` — and reads three formats, chosen by file name and confirmed against the bytes: JUnit XML (one file, **or a whole directory** of them, which is how a runner that writes one file per suite is declared: nen reads every `*.xml` under it, sorted, and merges them), the `testResults[].assertionResults[]` JSON a JavaScript runner writes with its JSON reporter, and the JSON test summary a **declared** result-bundle extraction step writes — nen opens no result bundle itself, because the only supported way to read one is a program no declaration named. The eight outcome words the three formats spell between them collapse to three statuses: an `error` is a **failure**, `pending`/`todo`/`disabled` are **skips**, an `Expected Failure` is a **pass**, and a word nen has not met is a refusal naming it rather than a guess that could make a red suite look green. **A run that failed is still parsed** — the one place this verb disagrees with `nen shu coverage`, because a failing suite is the report anybody asked for — while a run that started *nothing* (a dry run, an unmet precondition, a program that would not spawn) parses nothing, since the file on disk is then certainly an earlier run's. **The failures never move the exit code**, in either direction: it is the run's, and under `--from-artifacts` — which reads the declared results and starts no process at all, the one second read gate in izanami's automation-policy table — it is about the read, so a report full of failures that parsed cleanly exits 0. A damaged report is a refusal naming the file and the field, never a number: a case with no name, a count that is a string, a summary accounting for more tests than it ran, or an `*.xml` inside a directory artifact that is not a test report at all. Suite names that resolve inside the repository are reported relative to its root, so a `--json` document does not carry the path of whoever ran it ([#144](https://github.com/zheref/nen/pull/144))

## v0.3.0 — 2026-09-08

### Fixed

- **shu** — `nen shu detect` proposes `gradle-android`'s two screenshot rows only where the lane's own build actually applies the plugin whose task they run. `{gw} verifyPaparazziDebug` (as `ui-test`, and as `test` wherever `{unitTestTask}` answered) was written into every `gradle-android` lane whose wrapper `detect` could resolve — the markers confirm a wrapper, a settings file and the Android *application* plugin, and none of the three says anything about Paparazzi — so a lane without it got a declaration whose first run is `Task 'verifyPaparazziDebug' not found in root project`, stored unread by `scaffold init --accept-detected`. Both rows are now gated by a `crossChecks` entry in the pack: four spellings count as applied (`id("app.cash.paparazzi")`, `id 'app.cash.paparazzi'`, `apply plugin: 'app.cash.paparazzi'`, and `alias(libs.plugins.paparazzi)`), and the id must be the **argument of an application** rather than merely present — a `testImplementation("app.cash.paparazzi:paparazzi-annotations:…")` names this plugin's artifacts and applies nothing, so a substring reading proposed the same broken row one indirection in. The alias is resolved in the catalogue **its own accessor names**, among the `gradle/*.versions.toml` files at the lane root (`libs.` is `gradle/libs.versions.toml`, a second catalogue is addressed by its own file stem, and a `testLibs.` accessor is never answered by `libs`), matched on the **whole key** Gradle generates — `libs.plugins.compose.paparazzi` is the `compose-paparazzi` entry or nothing — with the catalogue read as TOML (`#` to end of line, either line ending) and the build files read with the script stripper, so a commented-out application is not one in either language. Only **modules the lane's own settings file `include(…)`s** are read: a root `plugins` block naming the plugin `apply false` applies it nowhere, and a build file in a directory Gradle never configures is named as outside the build rather than counted. The answer is three-valued: `applied`, `absent`, and **`unknown`** for an `alias(…)` no catalogue of that name resolves, a settings file that builds its catalogues itself with `versionCatalogs {`, a dynamic `apply(…)`, a **root** build file that configures its modules from the top (`subprojects {`, `allprojects {` — the one signal the root is read for, never the id), or a `buildSrc/` or `build-logic/` whose convention plugins nen does not read. `absent` and `unknown` both withhold, as a **seat** that says which of the two it was, names every build file nen opened *and* every one it deliberately did not, and carries the honest alternative from the pack — for `test` the plain JVM row `{gw} :<module>:test` (never `testDebugUnitTest`), for `ui-test` that no screenshot task exists to propose and instrumented UI tests are unsupported on this stack. A plugin applied inside a **nested build** (a directory with its own wrapper or settings file) is named and not counted: it is applied to a build this lane's wrapper never runs. A row that also stops at an unanswered token now states **both** reasons (`… -- and independently: …`) instead of claiming the token is all it still needs. The plugin id lives only in the pack, pinned by a test that fails if `detect.ts` ever spells it ([#134](https://github.com/zheref/nen/pull/134), closes #128)
- **shu** — `nen shu detect` sorts every directory listing it walks, so one tree proposes one document. `readdirSync` returns the host's order and the host is not one host — this repository's suite runs under Node and the shipped binary is Bun, and the two answer the same unchanged directory differently — which changed the lane order, the marker list of a lane that matched twice, and (the correctness half) which of two lanes competing for one name got the bare one. The order is BYTE order everywhere, never `localeCompare`, so it does not depend on the machine's locale either: a repository with `apps/Beta` and `apps/alpha` now always proposes them in that order, in the lane list, in `--lane`'s refusal and in the key order of the written file ([#119](https://github.com/zheref/nen/pull/119), closes #116)
- **board** — `nen board render` and `nen board diff` validate the board file at the read seam and refuse a malformed board at exit 2 naming the file, row and field, instead of crashing with a raw `TypeError` (render) or silently diffing the string `"undefined"` (diff). Undeclared top-level board fields are now dropped from their `--json` output, as `build` already did for rows ([#99](https://github.com/zheref/nen/pull/99), closes #92)
- **epic** — `nen epic next-wave` treats every ref spelling inside a `blocked by` / `blocks` clause (bare `#N`, `owner/repo#N`, a markdown link) as an edge, never the line's identity, and finds the clause even when a prose `blocked by` precedes it; a line whose only ref sits inside a clause is reported as unparsed instead of becoming a phantom child ([#103](https://github.com/zheref/nen/pull/103), closes #97)
- **parse** — izanami's automation-policy classifier answers a verb that is mutating in every form (`tag cut`, `label apply`, `pr retarget`, …) as `mutating` with its own reason even when `--` is present, instead of a generic `unknown`; the refusal is unchanged ([#104](https://github.com/zheref/nen/pull/104))
- **parse** — the shell-metacharacter refusal renders the caller's line safely when it contains a quote or backslash ([#104](https://github.com/zheref/nen/pull/104))
- **backlog** — `nen backlog order --rows-from` validates the row document at the read seam and refuses a wrong shape at exit 2 naming the file, row and field — including `backlog fetch --json`'s own output, which must be reshaped first — instead of crashing with `{} is not iterable` ([#107](https://github.com/zheref/nen/pull/107), closes #105)

### Added

- **shu** — `nen shu deploy` sends a build to a declared, **named** destination and to nothing else, and it takes **two flags with no single-flag path to acting**: `--target` says where (required, with no default ever) and `--run` says now. Without `--run` the verb prints the fully resolved plan — the destination substituted into the argv, every precondition asserted, each step as `would run:` — and spawns nothing, at exit 0; `--dry-run` is the explicit spelling of that same form and `--run --dry-run` together is exit 2 rather than a guess. It is the same dry-run-first gate `nen label apply --run` and `nen wake fire --run` carry, on the one verb in this family whose blast radius is other people's users, and it makes `shu deploy` the one executing row izanami classifies `write-flag-gated` rather than `dry-run-gated`: without `--run` the line is **read-only** because nen spawns nothing whatever the declaration says, a quoted `--run` it cannot prove absent is refused, and with `--run` in any spelling nen's own argv reader accepts it is mutating. `project.targets` is now parsed (`args` appended to the lane's own `deploy` argv — refused on a multi-step row, because which step reaches the destination is a guess, and refused, like any other argv, when they carry one of the reference pack's placeholder tokens; `requiresEnv` naming variables nen asserts are SET and whose values it never reads, compares, logs or prints, de-duplicated and held to a shell identifier at load, and asserted once when the lane's own preconditions already name one; `unsupported` for the destination that has no command line at all — a hosting provider's own push integration, a CI action — refused at exit 4 in the repository's own words, with the sentence required rather than just the key), and a key one edit from one of those four (`arg`, `requireEnv`) is refused by pointer naming the key it meant rather than preserved into silence. The report carries a `target` block (`{name, args, requiresEnv}`, `null` on every other verb) so a deploy that ran says where it went. The destination is resolved **after** the lane, the verb, the host and the placeholders and before the preconditions, which makes a written `deploy` seat reachable for the first time: a lane whose declaration says it has no deploy answers exit 4 with that sentence whatever `--target` says, instead of the old "no targets declared" that sent a maintainer to write a block which could not have helped. `nen shu detect` proposes `"targets": {}` on every stack and a destination on none, with a per-lane note carrying the reference pack's own word on `deploy`, the shape to write, and the rule that a credential value never goes in a committed file ([#135](https://github.com/zheref/nen/pull/135), closes #125)
- **cli** — a value flag given twice is now a usage error naming the value already read, family-wide, instead of silently taking the last one: `nen shu deploy --target preview --target production` used to send the build to production because of argument ORDER, with nothing on screen saying which of the two nen took. A flag that takes several values still takes them as one comma-separated value, and a repeated boolean is untouched ([#135](https://github.com/zheref/nen/pull/135), closes #125)
- **scaffold** — `nen scaffold init` is idempotent within a release but not across one, and now says so: the declaration it writes is `shu detect`'s proposal, which gained `"targets": {}` in this release, so a tree scaffolded by **v0.2.0** and re-run here reports the declaration `refused` (*already exists with different content*) rather than `skipped`. That is the verb's existing rule — it never overwrites a declaration and has no `--force` — applied to a proposal that grew; the block it would have written is printed above the refusal, an absent `targets` and an empty one behave identically, and every other step still reports `skipped` ([#135](https://github.com/zheref/nen/pull/135), closes #125)
- **shu** — `nen shu warmup` gets a working copy ready to iterate: refuses a dirty tree unless `--discard`, fetches and fast-forwards the trunk, creates the caller's branch, verifies the declared build and optionally the tests, printing every command under `--dry-run`. Every check that needs no mutation runs **before** `--discard` destroys anything, so a mistyped `--branch` costs nothing; `--discard` is `git reset --hard` then `git clean -fd` (never `-x`, never a second `-f`) and the tree is then **read again** — a nested repository or a dirty submodule that survived is named at exit 2 rather than reported as clean. It also refuses a half-finished merge/rebase/cherry-pick naming that operation's own `--abort`, and a detached `HEAD` carrying commits no branch and no remote-tracking ref reaches. The lane is resolved from the declaration on the branch it cut, not the tree it started in; a delegated `2` is reported as `1` (3/4/5 still pass through); the unrelated top-level `nen warmup` (registry pin sweep) is unchanged and both help texts say so ([#129](https://github.com/zheref/nen/pull/129), closes #124)
- **scaffold** — `nen scaffold init` is stack-aware for an existing repository (`--stack <id>` or `--accept-detected`, and it refuses naming both rather than guess one; `nen/contract.json`'s project block written into absence; the four taxonomy files still under `schemas/` **copied** into `nen/` with the `git rm` line printed and a differing pair refused; the stack's CI workflow from a bundled `templates/<name>/` data pack; `.nen/` appended to `.gitignore`; and a closing `nen shu tools` **check** that names the `--install` command instead of running it, unless `--install-tools` says so) plus a `--dry-run` that writes nothing and spawns nothing, probes included — the three v0.2.0 writes and their output are unchanged, and a second run reports `skipped` per item; `nen scaffold new` scaffolds a fresh project for any supported stack (`--stack --name --dir`, an empty directory it refuses to merge into, `{{name}}` substituted into the template's files, and `nen/contract.json` proposed by `shu detect` off the marker it just wrote, so a scaffolded project and a declared one cannot disagree — every post-step printed and none run). Every path either verb writes stays inside the tree it was pointed at: `--hook-path` and `--canon-values-path` are refused at exit 2 when they resolve outside `--repo` (the containment rule `nen shu` already applied to a declared path, now shared), and the two writes that create a directory — `nen/contract.json` and `.github/workflows/nen-shu.yml` — are additionally checked against the **real** path, so a symlinked `nen/` or `.github/` is refused naming the link rather than followed. The generated workflow is pinned at the greater of this binary's version and a minimum `templates/index.json` declares (the first release carrying the `nen shu` verbs it runs), overridable with `--nen-ref vX.Y.Z` and refusing one below the minimum by name, with a note saying nen cannot verify offline that a release exists for a ref; it also declares `permissions: contents: read`. A filesystem failure mid-run is a `refused` row carrying the errno and the report still prints, `.gitignore` is appended to byte for byte (a CRLF file is no longer rewritten, and the action is `appended`/`would-append`), a symlinked legacy taxonomy file is refused rather than copied in under a taxonomy file's name, both verbs write the commit-msg hook `0755`, and `scaffold new` refuses the `init`-only flags it used to accept and ignore ([#131](https://github.com/zheref/nen/pull/131), closes #114)

- **docs** — README gains a "Day to day" section: pin the binary once, set up a repository's taxonomy, and the four verbs a maintainer runs most, each runnable as printed. `docs/USAGE.md`'s workflow 6 is corrected to match: `backlog fetch`, `backlog order` and `board build` do not compose by file, and the reshape between them is the caller's ([#106](https://github.com/zheref/nen/pull/106))
- **shu** — `nen shu coverage` runs the lane's declared coverage verb and parses its report (Istanbul/Vitest, xccov, Cobertura/JaCoCo XML, LCOV) into one shape with totals and per-target rows, read from the first entry under the verb's own `artifacts` whose format nen recognises. `--threshold` only reports `met` and never changes the exit code, in either direction, and it is compared against the **counts** rather than the rounded percentage the table prints, so a project at 79.996% does not clear a bar of 80. A dry run parses nothing and a failed run is not parsed at all — a report on disk may be a previous run's — and a report that is truncated, or states more covered lines than it has lines, is a refusal naming the file rather than a number. Row names that resolve inside the repository are reported relative to its root, so a `--json` document does not carry the path of whoever ran it ([#130](https://github.com/zheref/nen/pull/130), closes #123)

### Breaking / consumer notes

nen is still on a 0.x line, so a minor bump is the vehicle for a breaking change, not just features — every item under "Changed" above is one, and `nen/` replacing `schemas/` as the canonical taxonomy directory is the one every consumer meets first (`schemas/` is still read as a fallback for the whole v0.3 line, and that fallback is removed in v0.4.0). Two consumers pin nen by tag and neither moves on its own:

- hatsu's `nen.contract.json` declares `minimum "0.1"`, which resolves to `>=0.1.0 <0.2.0` — v0.3.0 falls outside that range by design. Its repin PR needs a contract bump to `"0.3"` plus an updated `pinned_ref`, reviewed against the behaviour changes above.
- akatsuki-ai's vendored `bootstrap/nen.sh` carries a `DEFAULT_REF` pinned to `v0.1.0` and needs the same explicit repin, plus `nen scaffold init --accept-detected` to move its four `schemas/` files into `nen/`.

## v0.2.0 — 2026-09-07

nen's second release, and the first minor bump on its independent 0.x line. While nen sits at 0.x, a minor is where a breaking change ships — semver only promises no breaking changes between minors once a project reaches 1.0, and every one of the behaviour changes below is exactly that kind of change, not a bug reclassified as a feature. This release closes every p1/p2 issue filed against v0.1.0, across the 22 PRs below, cut via the release PR [#88](https://github.com/zheref/nen/pull/88).

### Behaviour changes a caller must know

These are deliberate contract changes, not bugs — a caller pinned to v0.1.0 behaviour needs to account for every one of them before repinning.

- `nen loop slots` now requires `--local-cap`; it no longer defaults the local concurrency plane to 7. The way out: pass `--local-cap <n>` explicitly. ([#69](https://github.com/zheref/nen/pull/69))
- `nen label apply`, `nen ref parse`, and `nen color status` now exit 2, not 1, on a typo'd token — matching this CLI's own contract that exit 2 means "you typed it wrong". The message text is unchanged, only the code; a retry wrapper or script branching on exit 1 for a bad ref or a bad `--category` must switch to 2. ([#83](https://github.com/zheref/nen/pull/83))
- `nen warmup` now fails (exit 1) on a consumer with no recorded pin, and gains an `unpinned` finding `kind` carrying `"pinned": null` in `--json` (widened from `string` to `string | null`). This is fail-closed on purpose: a check that could not be performed must never render as one that came back clean. The way out: record the pin, or update a caller reading `finding.pinned` as always a string. ([#83](https://github.com/zheref/nen/pull/83))
- `nen changelog completeness` and `nen release preflight` now both default `--fragment-dir` to `changelog.d`, and both refuse an empty value, a value naming a file, or a value that cannot be read — instead of the two verbs silently disagreeing about where fragments live, or one of them resolving an empty flag to the repository root. Omit the flag to get the default; pass an existing directory otherwise. ([#83](https://github.com/zheref/nen/pull/83))
- `nen board render` and `nen stop` now escape `|` as `\|` and flatten embedded newlines to a single space in table cells, so a title carrying either no longer shifts every later column. A consumer doing its own naive `split("|")` over these tables must switch to splitting on `(?<!\\)\|`, or use the exported `parsePipeTable`. ([#83](https://github.com/zheref/nen/pull/83))
- A gates file, a `--reviewers` name, or `wake --author-pattern` can now be refused at load time for a pattern with a potentially exponential-backtracking shape (`(a+)+`, `(a|a)+`, a large finite repeat over an ambiguous body) or one that matches the empty string (`.*`, `a*`, `x?`). The refusal quotes the offending fragment and names a rewrite; `.+` still loads, and both shipped fixtures and every product-codes registry checked against this pass load unchanged. ([#86](https://github.com/zheref/nen/pull/86))
- A relative `--gates` now resolves against `--repo`, not the current working directory, and the resolved absolute path is printed in `--explain` and in `--json`'s `meta.identities.path`. A caller relying on the old cwd-relative behaviour should pass an absolute path instead, which is used as-is and is unchanged. `nen pr next-blocker --gates` shares the same resolver. ([#86](https://github.com/zheref/nen/pull/86))
- An error escaping the entry point (`import.meta.main`) now exits 1 with a single `nen: `-prefixed message, instead of an unhandled-rejection stack dump and whatever exit status the host runtime happened to choose. ([#86](https://github.com/zheref/nen/pull/86))
- `nen issue attach-sub` and `nen issue consolidate-close` now refuse — before any write — when a number in `--parent`/`--children` names a pull request rather than an issue, and `nen idea file` fails loudly (exit 1) when its read-back verification lands on a pull request instead of an issue. The way out: pass an issue number, or verify the object by hand when `nen idea file`'s refusal says the issue was filed anyway. ([#82](https://github.com/zheref/nen/pull/82), [#84](https://github.com/zheref/nen/pull/84))
- `nen issue consolidate-close` without `--severity-family <ns>:<family>` used to silently union every child's severity label onto the parent at exit 0 whenever the children carried more than one label of the same family. It now refuses at exit 1, before any write, naming the colliding family and its labels. The way out: pass `--severity-family <ns>:<family>` naming the family whose strongest label should win. ([#62](https://github.com/zheref/nen/pull/62))
- `nen issue chain-position` and `nen issue terminus` now refuse when `--issue` names a pull request, for the same reason. ([#71](https://github.com/zheref/nen/pull/71))
- Two of the refusals above are pinned to a machine-readable `--json` shape rather than left to text-matching: `nen issue attach-sub`/`nen issue consolidate-close`'s pull-request refusal is `{parent, children, pullRequests, refused: true, reason}`, and `nen issue chain-position`/`nen issue terminus`'s classifier refusal is `{issue, refused: true, reason}` — both in that key order. ([#82](https://github.com/zheref/nen/pull/82), [#84](https://github.com/zheref/nen/pull/84), [#71](https://github.com/zheref/nen/pull/71)) `nen pr ready --explain`'s identities line is the same kind of fact for a caller that only reads text output: it now prints the resolved absolute gates path rather than a bare relative one, matching what `--json`'s `meta.identities.path` reports. ([#86](https://github.com/zheref/nen/pull/86))
- `nen issue comment` is a new verb — a general comment plus a per-child close-comment channel for consolidation. ([#75](https://github.com/zheref/nen/pull/75))
- `nen repo scenario`, `nen canon resolve`, `nen parse futon`, `nen wc classify`, `nen stage triage`, `nen idea file`, `nen labels sync`, `nen scaffold init`, `nen issue file`, `nen issue consolidate-close`, `nen tag cut`, `nen pr next-blocker`, `nen pr cascade-main`, `nen release resolve-target`, and `nen release self-check` — 15 verbs in all — now require `--repo`, matching what each one's own usage line already promised. Omitting it used to fall through to a silent cwd default (reading the wrong repository, or surfacing a raw "no such file" from an unrelated directory); it now refuses at exit 2 naming the flag. ([#73](https://github.com/zheref/nen/pull/73))
- `nen pr fetch` never issues a write call — every `gh api` argv it builds now names its HTTP method explicitly, closing a path where an unnamed method could resolve to something other than a read. ([#59](https://github.com/zheref/nen/pull/59))
- `nen release preflight` now parses `RELEASE_HOLD` for truthiness instead of merely non-emptiness, so `RELEASE_HOLD=false` and `RELEASE_HOLD=0` no longer hold a release the variable's own value says should proceed. ([#63](https://github.com/zheref/nen/pull/63))
- `nen parse izanami` and `nen watch until`'s read-only certification is tightened at the classification seam: a command that used to certify as `[read-only]` — including some quoted or metacharacter-bearing forms — can now refuse instead. A watcher relying on the looser certification should re-verify its commands still classify as expected. ([#74](https://github.com/zheref/nen/pull/74), [#76](https://github.com/zheref/nen/pull/76))
- A malformed `$`-prefixed key inside `schemas/repos.json`'s `product_codes` (e.g. `$comment`) now loads silently, skipped as metadata, instead of being read as a real product code and refusing or mis-reporting downstream. No action needed unless a caller depended on the old refusal. ([#81](https://github.com/zheref/nen/pull/81))
