# Changelog

All notable changes to nen. Versions are git tags on `main`; a tag is not a release — see [Install](README.md#install).

## Unreleased

### Fixed

- **repo** — `nen repo resolve` and `nen repo scenario` refuse a `--repo` (or, for `resolve`'s no-token form, a current directory) carrying NEITHER `nen/repos.json` NOR the legacy `schemas/repos.json` at exit **2**, naming the file, instead of falling through to a generic exit-1 failure indistinguishable from an unresolved token or an unrecorded scenario. A missing registry is a PRECONDITION neither verb can proceed past at all — the same class of thing as an omitted `--repo` or `--from` beside a token, both already exit 2 in this family — not a data problem inside a file that opened fine. A registry that is present but malformed is unaffected and stays exit 1, matching how `nen commit format` already treats a malformed (as opposed to absent) `nen/workflow.json` (`nen repo inventory` never reads the registry and is unaffected) ([#153](https://github.com/zheref/nen/pull/153))
- **shu** — `eslint.config.js` adds `.claude/**` to its ignore list, beside `coverage/**`: `eslint .` was sweeping every sibling worktree under `.claude/worktrees/`, warning on a stale `eslint-disable` comment inside another effort's generated `coverage/lcov-report/*.js` on every `nen shu lint` run. `.gitignore` gains `.claude/worktrees/` (not the whole `.claude/` directory, which carries no tracked files today but may hold committed configuration later) ([#153](https://github.com/zheref/nen/pull/153))
- **shu** — `docs/USAGE.md`'s `nen shu dev` section now says, in the `device.name` matching paragraph, that the match is exact — a string comparison with no Unicode normalisation: a device name macOS writes with a typographic apostrophe (U+2019, as in `Sergio’s iPhone`) must be declared with that same character, never the straight `'` (U+0027) a keyboard types, or the probe's output will not match it ([#153](https://github.com/zheref/nen/pull/153))

### Added

- **pr**, **issue** — `nen pr edit-body --target <owner/name> --pr <n> --body-file <path>` and `nen issue edit-body --target <owner/name> --issue <n> --body-file <path>` replace an object's body OUTRIGHT with a file's bytes — no trimming, no template — through `gh pr edit --body-file` / `gh issue edit --body-file`, retiring the last hand-run `gh … edit --body-file` a mechanised choreography had to drop back to (the body-replacement half of the gap `issue comment` closed for posting). Both certify the number BEFORE any write, and — unlike `issue comment`, which deliberately accepts either object class — each refuses the other family's object at exit 2: `pr edit-body` reads `gh api repos/<target>/pulls/<n>` and refuses a 404/410 (worded so it never claims the number IS an issue, only that it is not a pull request), and `issue edit-body` reuses `readIssue`'s existing `issues/{n}` discriminator and refuses a number carrying a `pull_request` payload. `--dry-run` still performs that certifying read — this pair is not network-free, the same shape `issue attach-sub`/`consolidate-close` already have — then prints the target, the number, the byte count and the first/last line instead of writing. `--json`: `{ contract: "nen.pr.edit-body/v0.1" | "nen.issue.edit-body/v0.1", target, number, bytes, written, dryRun }`. Both are `dry-run-gated` in izanami's automation-policy table ([#151](https://github.com/zheref/nen/pull/151))
- **surface** — new family `nen surface` (`mirror generate`, `mirror check`): one skills directory rendered into the layout and frontmatter another agent surface documents for itself, and the drift check that says whether the committed copy is still an image of it. `nen surface mirror generate --source <dir> --surface codex|cursor --out <dir>` writes `<out>/<name>/SKILL.md` for every `<name>/SKILL.md` under `--source`: the **body verbatim**, the frontmatter reduced to the keys that surface documents, and — with `--invocation-prefix` — every `<prefix><name>` mention respelled the surface's own way. **Every per-surface difference is a row in `src/surface/rules.ts`, never a branch in the generator**, and each row carries the URL every fact in it was read from (read 2026-09-10): `codex` keeps `name`/`description` only, spells an invocation `$<name>`, and — having no markdown persona file — folds each `--agents` persona into a `## <name>` section of a generated `AGENTS.md`; `cursor` keeps the whole documented key table (`name`, `description`, `paths`, `globs`, `disable-model-invocation`, `icon`, `color`, `metadata`), spells it `/<name>`, and writes one subagent file per persona under `agents/`. A surface that documents **no** invocation spelling leaves the mention exactly as written — this verb never invents a syntax nobody published. The `<prefix>` itself is a flag and never a literal in this binary, for the same §3 reason [`canon mirror generate`](https://github.com/zheref/nen/blob/main/docs/USAGE.md#nen-canon-mirror-generate)'s `--header-template` is one. Every generated file carries `<!-- GENERATED by nen surface mirror (surface: <name>) -- do not edit; edit the source and regenerate -->` as its first **markdown** line — *after* the frontmatter fence, not above it, because every one of these surfaces identifies a skill by frontmatter at the start of the file and a banner on line 1 would produce a document the surface silently declines to load. `generate` writes only what changed, deletes an orphan whose source is gone (and the directory it emptied), and **refuses, before writing a byte, any destination that exists and carries no marker** — the case that makes it non-optional is `AGENTS.md`, which people write by hand and which an `--out` pointed one directory too high would otherwise destroy. `nen surface mirror check` regenerates in memory, writes nothing at all, and reports `missing`/`extra`/`stale`/`hand-edited` exactly as `canon mirror check` does, exit 1 on any drift; `stale` is where that verb's `--ref` sits here — the marker names the **surface**, so a mirror generated for one and checked against another was really generated and really is out of date. Refused at exit 2: an `--out` inside `--source` (the mirror would become part of its own source), a `--surface` with no row, a `--source` holding no `SKILL.md` (an empty generation would delete the whole mirror as orphaned), a `SKILL.md` with no frontmatter or missing a key the surface documents as required, and `--dry-run` on `check`. The mirror's filename universe has **two** conditions — a file must sit at one of the row's own locations **and** carry a generated marker — so a `SKILL.md` somebody wrote by hand in the mirror directory is never overwritten, never deleted as an orphan and never reported as `extra`, exactly like a `references/` file beside a generated skill; `check` and `generate` read that same list, so what one reports the other clears. On a surface that keeps personas as files, a persona that would mirror to an EMPTY frontmatter block (no fence in the source, or a fence holding only keys that surface does not read) is refused at exit 2 rather than written as a persona file with nothing for the surface to route on — on a surface whose personas are prose, the same file is fine ([#149](https://github.com/zheref/nen/pull/149))
- **wc** — new verb `nen wc squash --onto <ref> --message-file <file>`: folds every commit `git merge-base <onto> HEAD` finds into ONE, whose message is validated to the same shape `nen commit format` enforces (a Conventional Commits header ≤ 72 characters, trailers as `Key: value` lines in the final paragraph, and any attribution trailer this repository's `nen/workflow.json` does not admit refused — the same wording `nen commit format` already uses, now shared through `../schema/workflow.ts`'s `attributionRefusalMessages` rather than kept as two copies). Every refusal runs BEFORE a single write, all at exit 2: a dirty working tree (every uncommitted/untracked path named); `--onto` not an ancestor of HEAD (what `git merge-base` found instead, quoted); any commit in the range already reachable from this branch's `@{upstream}` (fetched first, through the seam) — "already published; squashing would rewrite pushed history". Fewer than two commits to fold is **not** a refusal: exit 0, one line, nothing moves. The mechanism is `git reset --soft <merge-base>` then `git commit -F <message-file>`, both through the seam — `reset --soft` only moves the branch ref and the index, so a commit that then fails leaves the original commits recoverable from `ORIG_HEAD` / the reflog, which the verb's own error names. `--dry-run` prints the commits that would fold and the message, spawning neither call. `--json` publishes `nen.wc.squash/v0.1`: `{ contract, onto, mergeBase, folded: [sha, ...], newSha, dryRun }`, `folded` oldest first. Never touches a remote beyond the read-only fetch the upstream check makes, never pushes, never force-anything ([#150](https://github.com/zheref/nen/pull/150))
- **schema** — `nen/workflow.json`'s `notifications` block admits `turn`: `"rung1"` (the default, and what an absent key reads as) or `"all"` — a closed two-value set, refused by pointer on anything else, exactly like every other key this loader validates (`nen schema check`'s FAIL row). It decides how loud an ORDINARY turn is — one with no gate: `"rung1"` rings only the first rung `notifications.rungs` lists, `"all"` rings every rung `rungs` lists, every turn. A gate always rings everything `rungs` lists regardless of `turn`, and `turn` can only **withhold** an escalation `rungs` already grants — it can never conjure a rung `rungs` does not list. nen reads and validates the key and fires none of the three rungs itself, exactly as the rest of `notifications` already works: this is policy data for whichever host hook rings them. `templates/workflow.json` now states it explicitly, `"rung1"`, with a one-line `$comment`, so `nen scaffold init`/`new` write it into every fresh policy file rather than leaving it implicit ([#155](https://github.com/zheref/nen/pull/155))

## v0.4.0 — 2026-09-10

### Added

- **pr** — `nen pr cascade-main` gains `--no-push`: fetch and merge exactly as it always has, then stop — never push, with the log saying `not pushed (--no-push)` and `--json` gaining `noPush: true` (`false` on every other call, never omitted). A conflicted merge's `--json` also gains `conflicts[]`, one entry per unmerged path from `git diff --name-only --diff-filter=U`: `kind` (`both-modified`, `add-add`, `modify-delete`, `delete-modify`) read off `git ls-files -u`'s stage table, and `ours[]`/`theirs[]` — the commits each side contributed to that path since the merge base (`git log --format=%H <mergeBase>..<ref> -- <path>`). Text output lists the same, one block per file. Neither flag changes the existing rule: this verb never runs `git merge --abort`, never picks a side, and never pushes over a conflict. `--no-push` still merges locally — a working-tree/index mutation — so izanami's automation-policy table keeps `cascade-main` `mutating` in every spelling, `--no-push` included ([#141](https://github.com/zheref/nen/pull/141))
- **repo** — nen declares itself: `nen/contract.json` (a `project` block only -- one lane, `nen`, stack `bun-cli`, since none of this release's seven reference stacks names a Bun-native CLI and the field is a free string everywhere it is read; `build`/`test`/`lint`/`dev`/`archive` running this repository's own `bun run` scripts, `coverage` adding `@vitest/coverage-v8` and an `lcov` reporter so `nen shu coverage` has a report to parse, and `ui-test`/`run`/`release`/`deploy` as declared `{"unsupported": "<why>"}` seats) and `nen/workflow.json` (the Hatsu policy block -- branch template, iteration checks, the coverage ladder, notification rungs, the allowed/forbidden commit trailers, the model matrix). `workflow.json` was read by nobody when this landed; the schema, the loader and `nen schema check`'s row for it arrive later in the same release, under the **schema** bullet below. `coverage/` and `Reports/` are added to `.gitignore` and to `eslint.config.js`'s ignore list, so a local `nen shu coverage` run leaves no residue for `nen shu lint` to trip over ([#140](https://github.com/zheref/nen/pull/140))
- **report** — new family `nen report` (`data`, `render`): the facts an effort's report is made of, and the fill that turns them into one. `nen report data --repo <path> --base <ref>` assembles ONE document (`nen.report.data/v0.1`) describing this branch against that base — the commits (`<base>..HEAD`, split on a unit separator so a subject carrying a tab stays one field), the changed files (`<base>...HEAD`, the merge-base set a pull request shows, a rename reported at its **destination** with git's own status token), the `evidence` rows, the lane's coverage report **if one is already on disk**, `.nen/proof/<lane>.json` and `.nen/last-stop.json` verbatim. It **reads and never writes**: four git reads and some file opens, no write path in any flag combination, which is what lets izanami classify it read-only. Every absence is `null` with the reason on stderr — no declaration, no lane, no artifact nen recognises, a report not written yet — because a report verb answering "there is none to show" six different ways is still answering; what is **not** folded into a null is a git command that FAILS, so an unresolvable `--base` is exit 2 naming the ref with nothing read, and a failed `git log`/`git diff` is refused rather than reported as a branch with nothing on it. `--tiers <file>` labels each changed file from a caller-supplied `{ "<tier>": ["<prefix or glob>"] }` table whose **key order is the precedence**; a pattern with no `*`/`?` matches as a path prefix **on segment boundaries** (`src/report` never claims `src/reporting.ts`) and one with them as a narrow glob. `coverage` is parsed by `nen shu coverage`'s own reader (`src/shu/coverage/parse.ts`), so the two verbs cannot disagree about what an lcov file says — the difference is that this one spawns nothing and reads what is there. `evidence` is an empty list in this release **and the empty list is the seam**: those rows belong to `nen shu evidence`, which owns `project.evidence`, and the field ships now so a template written against this contract does not change shape when that verb lands. `repo` carries the checkout's directory NAME and never its absolute path — this document gets filled into a report that gets pasted into a pull request. `nen report render --template <file> --data <file> --out <file>` fills a template with that document: the WHOLE language is `{{token}}` (HTML-escaped), `{{{token}}}` (raw), `{{#each <list>}}…{{/each}}` (nested, with `{{.}}` and `{{@index}}`) and `{{#if <key>}}…{{/if}}` — no helpers, no partials, no comments, no expressions, because a program in a data file is a thing nobody reviews. A token the data has not got is exit 2 **naming it**, since a blank cell in a published report reads as a fact; a present `null` renders empty (the document's own "nothing to say") and an object or list reaching a value tag is refused rather than printed as `[object Object]`. `--out` must resolve inside `--repo` **with symlinks resolved**, and `--dry-run` parses, renders and throws the result away — so its refusals are the real run's — printing every token the template names, and listing them on a refusal too so the advice to run it is not a loop ([#142](https://github.com/zheref/nen/pull/142))
- **shu** — `nen shu test-report` runs the lane's declared **`test`** command and parses the results it produced into one shape: a row per test (`name`, `suite`, `status`, `durationMs`) and the four counts, under `nen.shu.test-report/v0.1`. It declares nothing of its own — it runs `project.verbs.<lane>.test` and reads *that* row's `artifacts` — and reads three formats, chosen by file name and confirmed against the bytes: JUnit XML (one file, **or a whole directory** of them, which is how a runner that writes one file per suite is declared: nen reads every `*.xml` under it, sorted, and merges them), the `testResults[].assertionResults[]` JSON a JavaScript runner writes with its JSON reporter, and the JSON test summary a **declared** result-bundle extraction step writes — nen opens no result bundle itself, because the only supported way to read one is a program no declaration named. The eight outcome words the three formats spell between them collapse to three statuses: an `error` is a **failure**, `pending`/`todo`/`disabled` are **skips**, an `Expected Failure` is a **pass**, and a word nen has not met is a refusal naming it rather than a guess that could make a red suite look green. **A run that failed is still parsed** — the one place this verb disagrees with `nen shu coverage`, because a failing suite is the report anybody asked for — while a run that started *nothing* (a dry run, an unmet precondition, a program that would not spawn) parses nothing, since the file on disk is then certainly an earlier run's. **The failures never move the exit code**, in either direction: it is the run's, and under `--from-artifacts` — which reads the declared results and starts no process at all, the one second read gate in izanami's automation-policy table — it is about the read, so a report full of failures that parsed cleanly exits 0. A damaged report is a refusal naming the file and the field, never a number: a case with no name, a count that is a string, a summary accounting for more tests than it ran, or an `*.xml` inside a directory artifact that is not a test report at all. Suite names that resolve inside the repository are reported relative to its root, so a `--json` document does not carry the path of whoever ran it ([#144](https://github.com/zheref/nen/pull/144))
- **schema** — `nen/workflow.json` is a file nen validates: the delivery loop's **policy**, as data, beside the `nen/contract.json` that says what nen executes. Every key is optional and carries a default, so an ABSENT file is a full policy rather than none — `nen schema check` gains a `nen/workflow.json` row reading `absent (defaults apply)` (deliberately not the contract row's `absent (optional)`: one means *nothing to read*, the other *a policy made of defaults*), naming the ladder, the branch template and the trunk when the file is there, and FAILing by **pointer** when it is there and wrong. `--json`'s `checks[]` carries the row last. The blocks are `branch` (`template`, which must contain `{descriptor}` — a template without it renders one branch name for every effort — and `base`, held to a git branch name a shell reads only once, because it is interpolated into a generated hook), `iteration`, `tests`, `coverage` (whole percentages 0–100 that must **ascend**: nen will not guess which of three rungs was mistyped), `launch`, `reports` (whose `dir` and `captures` are repo-relative with no `..`), `notifications`, `commits`, `monitor`, and an **open** `models` map. Unknown keys are preserved verbatim, and a key one edit from one nen reads is refused by pointer *because* they are — `{"coverage": {"minimun": 90}}` would otherwise be kept, read by nobody, with the ladder silently holding the default the repository meant to change; the near-miss rule `project.targets` already applies, shared rather than copied, and never applied inside `models`. Three fields have no default at all (`models`, `launch.default`, `iteration.lane`), because each would be nen inventing a name rather than a number ([#146](https://github.com/zheref/nen/pull/146))
- **commit** — `nen commit format --repo <path>` refuses, at exit 2, a `--trailer` whose key is attribution-shaped and is not listed in that repository's `commits.allowedAttributionTrailers`, naming the trailer and the file. Attribution-shaped is an enumeration a reader can audit (`Assisted-by`, `Claude-Session`, `Co-Authored-By`, `Generated-by`, `Generated-with`, `Reviewed-by`, `Signed-off-by`) plus every key the file's own `forbiddenTrailers` adds, matched **without regard to case** because every tool that reads the finished commit does. With no workflow file nothing is refused and the verb behaves exactly as it always has; the policy is opened only when the invocation carries a `--trailer`, and a workflow file that is present and malformed is exit **1** naming the pointer — nen will not shape a message under a policy it could not read ([#146](https://github.com/zheref/nen/pull/146))
- **scaffold** — `nen scaffold init` and `nen scaffold new` write a default `nen/workflow.json` into absence, and **generate both git hooks out of it**. The commit-msg hook gains a refusal for every attribution trailer the policy does not admit — resolved once and baked in **as data**, so the hook needs no nen on `PATH` at the moment of commit and cannot drift from the policy between runs — and it fires on **every** commit rather than only an automated one, because a trailer nobody wants in the history is unwanted whoever typed it. A new generated `pre-commit` hook refuses a commit made on `branch.base` (a detached `HEAD` reports no branch and is allowed through, so a rebase or a bisect still finishes), written beside the commit-msg hook in `--hook-path`'s own directory, with the same `unchanged`/`refused`/`--force`-plus-`.bak` ladder — now one implementation for both hooks rather than two copies of one promise. `.gitignore` upkeep appends the policy's `reports.dir` beside `.nen/`, deciding each entry separately so a file carrying one gets the other. A policy that is already there **wins and is never overwritten** (the hooks are generated from it); one that is there and malformed refuses the whole run at exit 2 before the first write. The written default admits exactly the two trailer keys `--agent-trailer` and `--run-trailer` named — nen ships no convention — and every other byte of it is a bundled data file (`templates/workflow.json`), so a reviewer can read what nen would write into somebody's repository without reading a line of TypeScript ([#146](https://github.com/zheref/nen/pull/146))
- **stop** — `nen stop --mark` writes `.nen/last-stop.json` under `--repo` (`{ contract, who, gate, notified, at }`, creating `.nen/` if needed) so a hook on the caller's own host can ring the OS-notification and audible rungs. **Rungs 2–3 stay the host's**: nen only ever shells out to `git` and `gh`, neither is a notification primitive, and this verb still fires nothing — it states the fact and the host acts on it, exactly as it already does for rung 1. The marker is written last, after every refusal, replaces an existing one (the latest stop is the one to ring for), and is the only form of this verb that writes anything, which is why izanami now classifies `stop` **write-flag-gated** on `--mark` rather than plain read-only; `--mark --template` is exit 2, and a marker that cannot be written is exit 1 with the errno ([#146](https://github.com/zheref/nen/pull/146))
- **shu** — `project.launch` and `nen shu dev|run --target <name>`: a local run that lands on a declared **device**. The block is `{ "<name>": { verb, args, device, after, unsupported, why } }`, a project-level map beside `project.targets` and deliberately not folded into it — `targets` says where a build is *sent*, `launch` says which device a local run lands on, and one map would have made `--target production` on `dev` resolve to a destination that sends nothing. The flag is **optional** here and has no default ever, so a bare `nen shu dev` is exactly the line it was before any target existed. Given, the verb becomes three things in order: the declared `device.resolve` probe (spawned through the **captured** seam, because nen has to read it), the lane's own verb interactively with the target's `args` appended, then the target's `after` steps with `{device.id}` and `{artifact}` substituted — `{artifact}` being the first entry of the verb's own `artifacts`. `device.name` is matched **exactly** against the probe's output, as JSON (a `name` property, with `identifier`/`id`/`udid`/`serial` from the same object, one of its direct children, or up to two enclosing objects — the shape a probe that puts the name and the id in *sibling* sub-objects prints) or as plain lines (the line carrying the name, and its first token of six-plus characters that also carries a digit, so a trailing status word is never read as an id); a `kind: "simulator"` device with no probe resolves to its own name and spawns nothing. Nen picks no device: there is no prefix match, no case fold and no "the only one connected", a device the probe did not name is **exit 5 listing what it did offer**, and a name that **two** id-bearing candidates carry is exit 5 naming both — plain output has no field boundaries, so a declared `Handset` is carried by the `Handset Pro` row too, and resolving the first would put the build on somebody else's device at exit 0 (one id reached twice is not an ambiguity). Refused before anything spawns, at exit 2: a `--target` naming no declared key (listing what is declared), a target declared for the other long-running verb, `args` on a multi-step row, `{artifact}` on a verb declaring none, `{device.id}` on a target with no device, and a device that says neither how to find its id nor that it needs none; a target with `unsupported` answers exit 4 in the repository's own words. `--dry-run` prints all three thirds as `would run:` with the tokens **unfilled** plus one `substitutes:` line, and spawns nothing at all — the probe included, which is why [`nen parse izanami`](docs/USAGE.md#nen-parse-izanami) still classifies both verbs `dry-run-gated`. `--json` stays refused on these two without `--dry-run`, and its `target` is then `{ name, verb, args, device: { name, kind, id }, probe, after }`. The loader parses the block rather than preserving it, for `project.targets`' reason one release on: a key one spelling out (`arg`, `devices`, `resolver`, `verbs` — and the block key itself as `launches` or `Launch`, which the one-edit rule alone does not reach) is **refused by pointer naming the key it meant and which misspelling it is** — one letter out, the same word in a different case, or that key with an English plural on it — because preserved it would be read by nobody and two thirds of a launch would silently not happen. The near-miss rule the deploy-target block already had is widened the same way and now says which of the three shapes it matched, instead of calling all of them "one letter away" ([#143](https://github.com/zheref/nen/pull/143))
- **shu** — new verb `nen shu evidence --base <ref>`: matches `git diff --name-status <base>...HEAD` — through the seam, spawning no invocation the target repository declared, only `git diff` itself — against a new project-level `project.evidence` block (`globs`, required and non-empty; `mechanism`, one of `public-mirror` \| `files-changed` \| `embedded`; `scene` and `suiteSuffix`, both defaulted), derives each surviving file's **suite** and **scene** and reports them grouped suite → scene. Suite/scene derivation generalises KroApple's own `ci_scripts/pr_screenshots.sh` (`scene_of()`): the nearest ancestor directory whose name ends with `suiteSuffix` names the suite (suffix stripped), falling back to the immediate parent directory when no such ancestor exists; the scene is the basename with its extension, a trailing `.<n>` and the `test_snapshot_`/`test_` prefixes stripped, in that order. The glob matcher (`*`, `**`, `?`) is a small, dependency-free module of its own, with `**` correctly matching zero directories on either side (`**/*.png` matches a root-level file, `a/**/b` matches `a/b`). A repository with no `project.evidence` block is exit 2 naming it — the one usage refusal this verb has; no changed file matching a glob is exit 0 with an empty `rows`/`suites` set, never an error. `--json` publishes `nen.shu.evidence/v0.1`. `project.evidence` refuses a key one edit from one of its four, by pointer, exactly as `project.targets` already does ([#145](https://github.com/zheref/nen/pull/145))
- **shu** — `nen shu coverage` gains `--touched --base <ref>`: after the run and the parse, nen computes `git diff --name-only <base>...HEAD` in the repository root and narrows `targets` to the rows that diff names — file-grain formats (`istanbul-summary`, `lcov`) matched by exact path, package-grain ones (`cobertura`, `jacoco`) matched when a touched file sits **under** the package (its own path segments appearing in order, with the file itself left over), and `xccov-report` read at **file** grain only under this flag — nen descends `targets[].files[]` instead of stopping at the target row, because "this whole app was touched" is true of nearly every diff. `--touched` requires `--base`; either flag given without the other is exit 2. `--json` gains `touched: { base, files, matched, unmatched }`, and each row gains its own `met` when `--threshold` is also given, on the counts and never the rounded percentage. With `--threshold` absent, nen also loads `nen/workflow.json`'s `coverage.{minimum,recommended,ideal}` through the shared `src/schema/workflow.ts` loader — the same one `nen schema check` validates — and reports each row's own `band` instead: `under-minimum` / `minimum` / `recommended` / `ideal`, exposed as a tenth `ladder` key, `{ minimum, recommended, ideal, source, present }`. An **absent** policy file is the published 80/85/90 default rather than no ladder, so every touched row is still banded and `present: false` says the rungs were assumed rather than declared; a policy that is present and malformed is exit 1 naming the pointer, refused before the declared tool is spawned, since the ladder is read alongside `--threshold`'s number rather than in the middle of the report. The touched-file list is split with `rawLines` and never trimmed, so a path whose own name carries spaces still matches its row ([#147](https://github.com/zheref/nen/pull/147)). Neither ever moves the exit code, in either direction — the same rule `--threshold` itself has always followed (zheref/nen#91 v3 q16)
- **shu** — a captured verb may declare a **stall guard**, and nen runs the repository's own remedy when a step stops making progress: `"stall": { "elapsedMs": <n>, "quietMs": <n>, "onStall": { "exe", "argv" }, "maxStrikes": <n, default 2> }` on an invocation (it reaches every step declaring none) or on one `steps[]` entry (which wins). **Nen never knows what to kill and now does not have to**: some toolchains hang — a compiler process wedges, the build stops emitting and never finishes, and the fix is to kill the wedged *grandchild* and let the build respawn it — and which process that is, is exactly the toolchain knowledge `src/shu/run.ts` and `src/shu/render.ts` may not carry. The repository declares the remedy as ordinary argv (never a string: there is no shell) and nen contributes the two numbers that decide **when**. It fires once **both** budgets are past — total elapsed **and** a quiet window with no output — because a guard acting on silence alone would fire at a healthy build that legitimately went quiet early on; each firing restarts the quiet window and costs a strike, and after `maxStrikes` the step is reported **stalled** at exit 1. **Nen never signals the child it started**, at any strike count: on a stall it stops watching, stops waiting, releases its own hold on the process and says plainly that it is still running and is the caller's to stop — the alternative, waiting, is the thing the caller came to be rescued from. Declarable only where nen READS the output (`build`, `test`, `ui-test`, `lint`, `archive`, `coverage`, `test-report`); on `dev`/`run` — which hand the terminal to the child — and on `release`/`deploy` it is **exit 2 naming the set**, never accepted and quietly not honoured. Both budgets and `maxStrikes` are positive integers validated **at load, by pointer** (a default for either budget would be nen deciding what "too long" means for somebody else's build), `onStall` is parsed by the same reader every declared step goes through, and a key one spelling away from one of the four is refused rather than preserved into silence. `--dry-run` prints an `on stall:` line under the step it guards; `--json`'s `steps[].stall` carries the budgets **and** what happened (`strikes`, `at` in milliseconds into the step, `stalled`) — spending every strike and finishing green is the guard *working*, which a count alone cannot say. A stalled step reports `exitCode: null`, because the child never gave one. A step with no guard goes through the captured seam exactly as before ([#154](https://github.com/zheref/nen/pull/154))
- **seam** — `Seams` gains a third runner, `runStreamed`, for a child that must be WATCHED while it runs: output relayed as it arrives with the millisecond each chunk landed on, and an optional watcher consulted on an interval with `{ elapsedMs, quietMs }`. `run` hands back one buffer when the child is already over and `runInteractive` gives the output up entirely, so neither can answer "has this said anything in the last minute" — the question a stall guard is arithmetic over. The watcher's verdicts are `watch`, `reset` (restart the quiet window *after* whatever the watcher just did), `stop` (stop watching, keep waiting) and `abandon` (stop waiting too, leaving the child untouched); **nothing in this seam ever signals a child**. The window arithmetic is one shared function, so `ScriptedSeams` — which gains a `runStreamed` replaying a timeline a fixture states, `{ atMs, stream?, text? }` per event — proves a guard against the same rule the real runner applies to a real clock, with no test sleeping for a three-minute budget ([#154](https://github.com/zheref/nen/pull/154))
- **shu/commit** — a green `nen shu build` records **the tree it proved**, and new verb `nen commit check --repo <path> --require-proof <lane>` reads it back. The build writes `.nen/proof/<lane>.json` (`nen.shu.proof/v0.1`: `contract`, `lane`, `verb`, `treeHash`, `at`, `exitCode`) when every step exits 0, and **removes** an existing one when the build comes out red — a stale proof is a green answer to a question that has since been answered red, and it must never outlive the tree it proved. A dry run writes nothing and removes nothing: it ran no build, so it learned nothing about this tree in either direction. `treeHash` is git's own tree object for the **working copy**, not the index — the build ran with nothing staged and the check runs a moment before a commit with everything staged, so an index-based hash would disagree every time and the proof would be useless in the workflow it exists for. Both sides compute it identically through the seam with a **scratch index** (`GIT_INDEX_FILE` under `.nen/`, removed afterwards): `git add -A`, `git rm --cached` for `.nen/` (a `:(exclude)` pathspec exits 1 in every repository that already ignores `.nen/`), then `git write-tree`. The repository's own index is never read or written, no ref moves, nothing tracked changes — which is what lets `nen parse izanami` classify `commit check` **read-only**. The check exits 0 when the proof is there, is that lane's, and its tree is this tree; exit 1 naming which of the three differences it is (no proof — also what a red build since the last green one looks like; a different lane; the tree has moved, with both hashes); exit 2 for a missing flag, a lane that escapes the tree, or a proof present and unreadable, which is never folded into "absent". A proof is held to its VALUES and not only its field types -- another `contract` may mean something else by the same fields, and `verb`/`exitCode` are the file's own assertion that a green build produced it, so an edited line cannot turn a red build into a green verdict. It **reports and blocks nothing**: no commit is refused and no file is written. It is what makes "never commit over a red build" affordable — the alternative is rebuilding before every commit, or believing a sentence in a transcript. `nen report data` already carried `.nen/proof/<lane>.json` verbatim and is unchanged; it now imports the path from the module that writes it, so where a proof lives is one fact ([#154](https://github.com/zheref/nen/pull/154))

### Breaking / consumer notes

nen is still on a 0.x line, so a minor bump is the vehicle for a breaking change, not just features. Two of the additions above change what a verb that already existed does: `nen commit format --repo` now refuses an attribution-shaped `--trailer` the repository's policy does not admit, and `nen pr cascade-main --json` carries `noPush` on every call. Nothing was removed, so a `nen/contract.json` pinning `minimum: "0.3"` stays valid for every verb that existed in v0.3.0 — but the contract's zero-major rule reads `0.3` as `>=0.3.0 <0.4.0` *exactly*, out of range in both directions, so that pin does not admit a v0.4.0 binary and `nen shu tools` reports the row `present-but-wrong-version` at exit 5. Reading any of the ten additions below means an explicit repin — `minimum: "0.4"` plus a `pinned_ref` of `v0.4.0`, in the consuming repository's own PR. Neither moves on its own.

- **schema** — `nen/workflow.json` is a file nen validates and `nen schema check` gains a row for it; every key carries a default, so an absent file is a full policy rather than none and an un-scaffolded repository still passes.
- **report** — the new `nen report` family (`data`, `render`) assembles the facts of an effort against a base ref as one document and fills a template from them; neither verb exists anywhere on the v0.3 line.
- **shu** — `nen shu test-report` runs the lane's declared `test` (or reads its `artifacts`) and parses JUnit XML, `.xcresult`, vitest JSON and Gradle results into one row-per-test shape with the four counts.
- **shu** — `nen shu evidence --base <ref>` reads a new project-level `project.evidence` block and groups the evidence artifacts the diff changed into suite/scene rows.
- **shu** — a new project-level `project.launch` block plus `nen shu dev|run --target <name>` land a local run on a declared device; a v0.3.0 binary preserves `launch` as an unknown key but carries no `--target` that could read it.
- **shu** — `nen shu coverage` gains `--touched --base <ref>`, which narrows the rows to the files the diff names and bands each one against `nen/workflow.json`'s ladder when no `--threshold` is given.
- **pr** — `nen pr cascade-main` gains `--no-push`, and a conflicted merge's `--json` gains `conflicts[]`; `--json` now carries `noPush` on every call of the verb, never omitted.
- **commit** — `nen commit format --repo <path>` now refuses, at exit 2, an attribution-shaped `--trailer` the repository's `commits.allowedAttributionTrailers` does not admit — a refusal no v0.3.0 binary makes, so a repository that relies on it must pin 0.4.
- **scaffold** — `nen scaffold init` and `nen scaffold new` write a default `nen/workflow.json` into absence and generate both git hooks out of it: a `pre-commit` that refuses a commit on the trunk and a `commit-msg` that refuses an unadmitted attribution trailer.
- **stop** — `nen stop --mark` writes `.nen/last-stop.json` under `--repo` so a hook on the caller's own host can ring the notification and audible rungs; nen still fires nothing itself.
- **shu** — `nen shu build` now WRITES `.nen/proof/<lane>.json` on a green build and removes it on a red one, and asks git for a tree hash to do it (a scratch index; the repository's own is untouched). A repository that does not ignore `.nen/` will see the file in `git status`; `nen scaffold init` has always added the entry. Every executing verb's `--json` document gains a trailing `proof` key and every `steps[]` row a trailing `stall` key, both `null` where they do not apply
- **commit** — new verb `nen commit check --repo <path> --require-proof <lane>`, read-only, which reports whether this working copy is the tree a green build proved. `nen commit` now refuses a flag the named subcommand does not read, as `nen shu` and `nen issue` already do

- The `schemas/` fallback that v0.3.0 announced for removal **in this release** is still read, and its removal moves to **v0.5.0**: the four taxonomy files still resolve from a repository's legacy `schemas/` directory when `nen/` does not carry them, `nen schema check` still names every legacy read, and un-migrated consumers keep working unchanged through the v0.4 line. Every sentence that named the removal point (README's migration note, `docs/USAGE.md`'s, and the `LEGACY_FALLBACK_REMOVED_IN` the CLI quotes) now says v0.5.0, because a binary that announces its own version as the removal point while still reading the fallback is a binary that lies; the deletion is a change of its own, with its own tests, not a line in a release commit.

### Breaking / consumer notes

nen is still on a 0.x line, so a minor bump is the vehicle for a breaking change, not just features — every item under "Changed" above is one, and `nen/` replacing `schemas/` as the canonical taxonomy directory is the one every consumer meets first (`schemas/` is still read as a fallback for the whole v0.3 line, and that fallback is removed in v0.4.0). Two consumers pin nen by tag and neither moves on its own:

- hatsu's `nen.contract.json` declares `minimum "0.1"`, which resolves to `>=0.1.0 <0.2.0` — v0.3.0 falls outside that range by design. Its repin PR needs a contract bump to `"0.3"` plus an updated `pinned_ref`, reviewed against the behaviour changes above.
- akatsuki-ai's vendored `bootstrap/nen.sh` carries a `DEFAULT_REF` pinned to `v0.1.0` and needs the same explicit repin, plus `nen scaffold init --accept-detected` to move its four `schemas/` files into `nen/`.

## v0.2.0 — 2026-09-07

nen's second release, and the first minor bump on its independent 0.x line. While nen sits at 0.x, a minor is where a breaking change ships — semver only promises no breaking changes between minors once a project reaches 1.0, and every one of the behaviour changes below is exactly that kind of change, not a bug reclassified as a feature. This release closes every p1/p2 issue filed against v0.1.0, across the 22 PRs below, cut via the release PR [#88](https://github.com/zheref/nen/pull/88).

### Behaviour changes a caller must know

These are deliberate contract changes, not bugs — a caller pinned to v0.1.0 behaviour needs to account for every one of them before repinning.

- `nen loop slots` now requires `--local-cap`; it no longer defaults the local concurrency plane to 7. The way out: pass `--local-cap <n>` explicitly. ([#69](https://github.com/zheref/nen/pull/69))
- `nen label apply`, `nen ref parse`, and `nen color status` now exit 2, not 1, on a typo'd token — matching this CLI's own contract that exit 2 means "you typed it wrong". The message text is unchanged, only the code; a retry wrapper or script branching on exit 1 for a bad ref or a bad `--category` must switch to 2. ([#83](https://github.com/zheref/nen/pull/83))
- `nen warmup` now fails (exit 1) on a consumer with no recorded pin, and gains an `unpinned` finding `kind` carrying `"pinned": null` in `--json` (widened from `string` to `string | null`). This is fail-closed on purpose: a check that could not be performed must never render as one that came back clean. The way out: record the pin, or update a caller reading `finding.pinned` as always a string. ([#83](https://github.com/zheref/nen/pull/83))
- `nen changelog completeness` and `nen release preflight` now both default `--fragment-dir` to `changelog.d`, and both refuse an empty value, a value naming a file, or a value that cannot be read — instead of the two verbs silently disagreeing about where fragments live, or one of them resolving an empty flag to the repository root. Omit the flag to get the default; pass an existing directory otherwise. ([#83](https://github.com/zheref/nen/pull/83))
- `nen board render` and `nen stop` now escape `|` as `\|` and flatten embedded newlines to a single space in table cells, so a title carrying either no longer shifts every later column. A consumer doing its own naive `split("|")` over these tables must switch to splitting on `(?<!\\)\|`, or use the exported `parsePipeTable`. ([#83](https://github.com/zheref/nen/pull/83))
- A gates file, a `--reviewers` name, or `wake --author-pattern` can now be refused at load time for a pattern with a potentially exponential-backtracking shape (`(a+)+`, `(a|a)+`, a large finite repeat over an ambiguous body) or one that matches the empty string (`.*`, `a*`, `x?`). The refusal quotes the offending fragment and names a rewrite; `.+` still loads, and both shipped fixtures and every product-codes registry checked against this pass load unchanged. ([#86](https://github.com/zheref/nen/pull/86))
- A relative `--gates` now resolves against `--repo`, not the current working directory, and the resolved absolute path is printed in `--explain` and in `--json`'s `meta.identities.path`. A caller relying on the old cwd-relative behaviour should pass an absolute path instead, which is used as-is and is unchanged. `nen pr next-blocker --gates` shares the same resolver. ([#86](https://github.com/zheref/nen/pull/86))
- An error escaping the entry point (`import.meta.main`) now exits 1 with a single `nen: `-prefixed message, instead of an unhandled-rejection stack dump and whatever exit status the host runtime happened to choose. ([#86](https://github.com/zheref/nen/pull/86))
- `nen issue attach-sub` and `nen issue consolidate-close` now refuse — before any write — when a number in `--parent`/`--children` names a pull request rather than an issue, and `nen idea file` fails loudly (exit 1) when its read-back verification lands on a pull request instead of an issue. The way out: pass an issue number, or verify the object by hand when `nen idea file`'s refusal says the issue was filed anyway. ([#82](https://github.com/zheref/nen/pull/82), [#84](https://github.com/zheref/nen/pull/84))
- `nen issue consolidate-close` without `--severity-family <ns>:<family>` used to silently union every child's severity label onto the parent at exit 0 whenever the children carried more than one label of the same family. It now refuses at exit 1, before any write, naming the colliding family and its labels. The way out: pass `--severity-family <ns>:<family>` naming the family whose strongest label should win. ([#62](https://github.com/zheref/nen/pull/62))
- `nen issue chain-position` and `nen issue terminus` now refuse when `--issue` names a pull request, for the same reason. ([#71](https://github.com/zheref/nen/pull/71))
- Two of the refusals above are pinned to a machine-readable `--json` shape rather than left to text-matching: `nen issue attach-sub`/`nen issue consolidate-close`'s pull-request refusal is `{parent, children, pullRequests, refused: true, reason}`, and `nen issue chain-position`/`nen issue terminus`'s classifier refusal is `{issue, refused: true, reason}` — both in that key order. ([#82](https://github.com/zheref/nen/pull/82), [#84](https://github.com/zheref/nen/pull/84), [#71](https://github.com/zheref/nen/pull/71)) `nen pr ready --explain`'s identities line is the same kind of fact for a caller that only reads text output: it now prints the resolved absolute gates path rather than a bare relative one, matching what `--json`'s `meta.identities.path` reports. ([#86](https://github.com/zheref/nen/pull/86))
- `nen issue comment` is a new verb — a general comment plus a per-child close-comment channel for consolidation. ([#75](https://github.com/zheref/nen/pull/75))
- `nen repo scenario`, `nen canon resolve`, `nen parse futon`, `nen wc classify`, `nen stage triage`, `nen idea file`, `nen labels sync`, `nen scaffold init`, `nen issue file`, `nen issue consolidate-close`, `nen tag cut`, `nen pr next-blocker`, `nen pr cascade-main`, `nen release resolve-target`, and `nen release self-check` — 15 verbs in all — now require `--repo`, matching what each one's own usage line already promised. Omitting it used to fall through to a silent cwd default (reading the wrong repository, or surfacing a raw "no such file" from an unrelated directory); it now refuses at exit 2 naming the flag. ([#73](https://github.com/zheref/nen/pull/73))
- `nen pr fetch` never issues a write call — every `gh api` argv it builds now names its HTTP method explicitly, closing a path where an unnamed method could resolve to something other than a read. ([#59](https://github.com/zheref/nen/pull/59))
- `nen release preflight` now parses `RELEASE_HOLD` for truthiness instead of merely non-emptiness, so `RELEASE_HOLD=false` and `RELEASE_HOLD=0` no longer hold a release the variable's own value says should proceed. ([#63](https://github.com/zheref/nen/pull/63))
- `nen parse izanami` and `nen watch until`'s read-only certification is tightened at the classification seam: a command that used to certify as `[read-only]` — including some quoted or metacharacter-bearing forms — can now refuse instead. A watcher relying on the looser certification should re-verify its commands still classify as expected. ([#74](https://github.com/zheref/nen/pull/74), [#76](https://github.com/zheref/nen/pull/76))
- A malformed `$`-prefixed key inside `schemas/repos.json`'s `product_codes` (e.g. `$comment`) now loads silently, skipped as metadata, instead of being read as a real product code and refusing or mis-reporting downstream. No action needed unless a caller depended on the old refusal. ([#81](https://github.com/zheref/nen/pull/81))
