- `nen pr converge --composite --require-head <sha> --body-requirements <path>` reports one readiness verdict at one pinned head (zheref/nen#483 AC-1): `pr ready` (in-process), the body check, the closing-issue links (into the default branch, every body closing keyword is a GitHub closing link and every GitHub closing link is named in the body) and the criteria coverage. Exit 0 only when all four hold; a read at another head, a head that moved, or a read that did not finish is exit 1 with stdout empty. `pr merge --delivery` gates on the same criteria and links conjuncts.
- `pr converge` takes `--catalogue` for the issue-sections catalogue, the name `body-check` and `merge --delivery` use; `--requirements-from` stays a deprecated alias on this verb (said on stderr; both given exits 2). Under `--composite` a read that did not finish, or was at another head, exits **3**, distinct from not ready (1). `pr merge --delivery` prints its transcript through `plainLine`, so a quoted verify row carries no control character.
