- `nen issue questions` exits 1 when a question is still open (zheref/nen#477 AC-1, AC-3): any open `OQ-{n}` row, any `[NEEDS …]` marker, or any malformed `OQ-{n}` row, and when an issue could not be read. Exit 0 only when every question is resolved or there is none, so a build or a selector can skip an issue on the exit alone.
- `nen issue questions --ref` takes a comma-separated batch of up to 100 issues (AC-4, SC-2): each counted on its own in one report, `--json` `{ contract, target, counts: { issues, blocking, clear, unread }, issues }`; an unreadable issue is an `unread` entry with its reason, never zero counts.
- **Behaviour change:** v0.26.0 exited 0 whatever the counts. A caller that read exit 0 as "the body was read" reads exit 1 with a non-empty stdout as "read, and a question is open".
