- `nen pr ledger post|read` (zheref/nen#510, #512 folded in) puts an effort's ledger slice on its pull request as ONE comment, contract `nen.pr.ledger/v0.1`: the phase ledger's entries, the usage ledger's totals, the caller's findings document and a `{ path, sha256, bytes }` proof index, under the marker `<!-- nen:ledger effort=<encoded id> sha256=<digest> -->`. `post` checks `--findings` against the caller's `--findings-schema` (a draft 2020-12 subset; any keyword it does not assert is refused at exit 2, and a failing document is exit 1 naming the JSON pointer, with nothing posted). It runs the private-name guard, then posts a comment or edits this login's one marked comment in place (`unchanged` when the digest matches). It refuses at exit 1 a slice over GitHub's 65,536-character limit, never truncating. `read` trusts only the authenticated login's comment (`foreign: n` counts the rest) and answers `ok`, `stale` (the PR moved on) or `could-not-read` (none, two, edited, or not the contract). `--restore` writes the phase ledger on a fresh clone and refuses to overwrite one that disagrees.
- New module `src/schema/jsonschema.ts`, a fail-closed JSON Schema subset validator for caller-supplied schemas. No dependency was added.
