- `nen pr ledger post|read` (zheref/nen#510, #512 folded in) puts an effort's ledger slice on its pull request as ONE comment, contract `nen.pr.ledger/v0.1`: the phase ledger's entries, the usage ledger's totals, the caller's findings document and a `{ path, sha256, bytes }` proof index, under the marker `<!-- nen:ledger effort=<encoded id> sha256=<digest> -->`. `post` checks `--findings` against the caller's `--findings-schema`, a draft 2020-12 subset. Refused at exit 2: any keyword it does not assert, a supported keyword with a malformed value, and a `$ref` outside subschema positions. A failing document is exit 1 naming the JSON pointer, with nothing posted. A credential's shape in the findings, a phase note, a step argv or a proof path is exit 1 (`secret-shape`, the field named). Proof paths are repository-relative, with one outside `--repo` refused at exit 2. The repository root in notes and step argv is written `.`. It runs the private-name guard over the caller's own text only, field by field (never nen's marker and summary), then posts a comment or edits this login's one marked comment in place (`unchanged` when the digest matches). It refuses at exit 1 a slice over GitHub's 65,536-character limit, never truncating. `read` trusts only a comment the authenticated login wrote and nobody else edited (read through GraphQL's `editor`; `foreign: n` counts the rest; `--login` names the poster for a token that cannot read `user`) and answers `ok`, `stale` (the PR moved on) or `could-not-read` (none, two, edited, or not the contract). `--restore` writes the phase ledger on a fresh clone and refuses to overwrite one that disagrees. A stale slice is restored and still exits 1.
