- **pr** — `pr ready` reads every `nen/gates.json` input at the pull request's BASE commit, not only `checks.excluded`: every `reviewers[]` key (`name`, `login_pattern`, `review_check_pattern`, `round_check_pattern`, `enrolment_check_pattern`, `bounded_policy_exempt`, `delivery_holistic_pass`, `approves_when_posted_at_head`), `default_approvers`, `approval_policy`, `base_reviewers`, `round_quorum`, `round_policy` (the stall bound and the round caps), `delivery` and `dependabot_carve_out`. One base read serves the identities and the exclusions, through the route #249 built. A head that loosens its own `login_pattern` or `round_quorum` no longer changes its own verdict. The checkout's own file applies only when the base could not be READ (a 403, the network, no base commit), with a `meta.warnings` line on every output. A base that declares no `nen/gates.json` never applies the checkout's file: `--reviewers`' own identities do when given, and otherwise there is no verdict (`unevaluated`, exit 1). A base file this build refuses gives no verdict either. `checks.excluded` is never taken from the checkout. An explicit `--gates` naming a file outside the checkout is the caller's word and supplies everything but `checks.excluded`, which stays the base's. A `--gates` naming the checkout's own `nen/gates.json` is read at the base, under any spelling or hard link. Any other `--gates` file inside the checkout is applied as head content, with a warning. `watch until --pr` and `pr merge` share the read. `pr merge` (both forms) and `watch until --until ready` refuse a `ready` judged on the checkout's file, and `pr merge --delivery` refuses a pull request that changes `nen/gates.json` or `nen/workflow.json`. `pr next-blocker` applies the same rule through `gh`: exit 2 where `pr ready` gives no verdict, and `--json` adds `identities { path, read }`. `pr ready --json` adds `meta.identities.read`: `base`, `local-fallback`, `gates-flag`, `local-unverified`, or `null` when `--reviewers` supplied the identities, which with a `nen/gates.json` in the checkout happens only on a base that declares none. `--explain` names the route on its identities line (refs #372).
- **Consumer note** — on unchanged inputs, a verdict judged from a worktree whose `nen/gates.json` differs from the base's now follows the base's file. A token without `contents:read` gets the fallback warning on every evaluation, and `pr merge` and `watch until --until ready` refuse such a `ready`. A repository whose base carries no `nen/gates.json` but whose checkout does now gets `unevaluated` from `pr ready` and exit 2 from `pr next-blocker` unless `--reviewers` (on `pr ready`) or a `--gates` file outside the checkout is passed; so does a base file this build refuses (repin nen). `pr merge --delivery` now reads the pull request's changed files, two more `gh` calls. `meta.identities.path` is `<owner>/<repo>@<sha>:nen/gates.json` when the identities were read at the base, where it used to be the local file's path. An unevaluated report can now carry `meta.identities.read` `base` or `local-fallback` and a `meta.declaredExclusionsSource` of `<owner>/<repo>@<sha>` when the base was read before a later GitHub read failed.
