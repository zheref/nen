- **pr** — `pr ready` reads every `nen/gates.json` input at the pull request's BASE commit, not only `checks.excluded`: reviewers and their login, review, round and enrolment patterns, `approves_when_posted_at_head`, `default_approvers`, `approval_policy`, `base_reviewers`, `round_quorum`, `round_policy` (the stall bound and the round caps), `delivery` and `dependabot_carve_out`. One base read serves the identities and the exclusions, through the route #249 built. A head that loosens its own `login_pattern` or `round_quorum` no longer changes its own verdict. When the base cannot be read, declares no file, or carries one this build refuses, the checkout's own file supplies the identities and a `meta.warnings` line on every output says so. `checks.excluded` is never taken from that fallback. An explicit `--gates` naming another file is the caller's word and supplies everything but `checks.excluded`, which stays the base's. A `--gates` naming the checkout's own `nen/gates.json` is read at the base. `watch until --pr` and `pr merge` share the read, and `pr next-blocker` applies the same rule through `gh`. `--json` adds `meta.identities.read` (`base`, `local-fallback`, `gates-flag`, `local-unverified`, or `null` for `--reviewers`), and `--explain` names the route on its identities line (refs #372).
- **Consumer note** — on unchanged inputs, a verdict judged from a worktree whose `nen/gates.json` differs from the base's now follows the base's file. A token without `contents:read` now gets the fallback warning on every evaluation, where it used to get identities from the local file silently. `meta.identities.path` is `<owner>/<repo>@<sha>:nen/gates.json` when the identities were read at the base, where it used to be the local file's path.
