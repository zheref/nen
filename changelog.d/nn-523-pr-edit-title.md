- `nen pr edit-title --target <owner/name> --pr <n> --title-file <path> [--dry-run] [--json]` replaces a pull request's title with the one line a file holds, through `gh pr edit --title`, and reads it back (zheref/nen#523). The title file is read verbatim, a leading byte-order mark and one trailing newline dropped, nothing else trimmed. A title that still holds a line break or another control character (U+0000–U+001F, U+007F), one with leading or trailing whitespace, one over 256 characters, an empty or whitespace-only title, an unreadable or non-UTF-8 file and a loose `--pr` are refused at exit 2 before any call; a number whose `pulls/<n>` answers 404/410 is refused at exit 2 before any write. The private-name guard checks the title (`pr edit-body`'s flags; exit 4, nothing written). It re-reads the title right before the write and stops at exit 1, nothing written, if it moved since certification; there is no etag pin, so a retitle after that re-read is overwritten, last-writer-wins. After the write the verb reads `pulls/<n>` again and compares exactly: a title GitHub stored differently, or a read-back that fails, is exit 1 (`--json` still says `written: true`). Titles GitHub returns are printed quoted with control and invisible characters escaped. `--dry-run` certifies, runs the guard and prints the single-quoted argv with the current and new title. `--json`: `nen.pr.edit-title/v0.1`, `{ contract, target, number, previous, title, written, readBack, dryRun, privateNameCheck }`. izanami classifies it dry-run-gated.
- Behaviour changes: none for an existing verb. `pr` refusals that list which subcommands read `--dry-run` or `--title-file` now name `pr edit-title` too.
