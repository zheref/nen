- `nen pr edit-title --target <owner/name> --pr <n> --title-file <path> [--dry-run] [--json]` replaces a pull request's title with the one line a file holds, through `gh pr edit --title`, and reads it back (zheref/nen#523). The title file is read verbatim, a leading byte-order mark and one trailing newline dropped, nothing else trimmed. A title that still holds a line break, an empty or whitespace-only title, an unreadable or non-UTF-8 file and a loose `--pr` are refused at exit 2 before any call; a number whose `pulls/<n>` answers 404/410 is refused at exit 2 before any write. The private-name guard checks the title (`pr edit-body`'s flags; exit 4, nothing written). After the write the verb reads `pulls/<n>` again and compares exactly: a title GitHub stored differently, or a read-back that fails, is exit 1. `--dry-run` certifies, runs the guard and prints the argv with the current and new title. `--json`: `nen.pr.edit-title/v0.1`, `{ contract, target, number, previous, title, written, readBack, dryRun, privateNameCheck }`. izanami classifies it dry-run-gated.
- Behaviour changes: none for an existing verb. `pr` refusals that list which subcommands read `--dry-run` or `--title-file` now name `pr edit-title` too.
