- Docs (zheref/nen#589): every documented `nen scaffold` command line now carries `--marker-env`, or says why it may be left out. The README's set-up section explains what the flag does (the variable the generated commit-msg hook reads to tell an automated commit from a human one), that `init` requires it with no default and refuses at exit `2` before any write without it, and that `scaffold new` is the one place it may be omitted (the hook is skipped and a printed post-step names the `init` line that installs it). The `schemas/` → `nen/` migration line in the README and USAGE now spells out `nen scaffold init --repo <path> --marker-env <VAR> --accept-detected`, the USAGE `init` and `new` examples say why each one does or does not pass the flag, and the "Onboard a repository's taxonomy" recipe gains the missing `--accept-detected` it needed to run at all.
- Behaviour changes (printed text only): in `templates/minimal/template.json`, the `gradle-android` and `xcode-ios` refusals that `scaffold new` prints now name `--marker-env <VAR>` in the `scaffold init` line they recommend, which previously exited `2` when copied.
