- New verb `nen audit deps` (zheref/nen#508): a directory's exact dependency pins, read from its lockfile and never by running its package manager, and with `--query` asked about at the OSV `querybatch` endpoint the caller's declaring contract names. `--contract` is an absolute path to a JSON file with a `dependencyAudit` object and `--row` names the row; Hatsu's `contracts/scans.json` `node` row is read unchanged. The row's `ecosystem` selects the reader: `npm` reads `pnpm-lock.yaml` (lockfileVersion 5, 6, 9), `yarn.lock` (berry and classic) and `package-lock.json` / `npm-shrinkwrap.json` (lockfileVersion 1, 2, 3); `SwiftURL` reads every `Package.resolved` at the root and inside an `.xcodeproj` or `.xcworkspace` bundle (formats 1, 2, 3), so the Swift audit is no longer carried out by hand. It is a port of Hatsu's interim `scripts/dependency_audit_resolve.mts`, and every lockfile case of that script's fixture passes here with the same verdict. Four exits: `0` clean (or resolved, without `--query`), `1` a finding at or above the row's `severityFloor`, an UNRATED id or an unqueried entry, `2` wiring (`nen exits audit` lists its own meaning of 2), `3` not scanned with the reason. A symbolic link, a truncated or unrecognised lockfile, a file over `maxLockfileBytes` (new, default 268435456), more than `maxEntries` entries or npm v1 nesting past `maxDepth` is not scanned. An entry from git, `file:`, a host off `registryHosts`, or a Swift pin on a branch or revision is unqueried and never clean. A malformed, non-JSON, oversized, redirected, failing, slow or unreachable OSV answer is not scanned, and a severity outside `severityLevels` counts as a finding. It reads no environment variable of its own; the runtime's `fetch` honours the host's proxy variables and TLS trust store, which USAGE documents as the host's network configuration. `--json` is `nen.audit.deps/v0.1`.
- Behaviour changes: `nen --help` lists 48 families, and `nen exits` gains two `audit deps` rows (`2` wiring, `3` not scanned). Hatsu's `swift` row as it stands names only `endpoint` and `ecosystem`, so `--row swift` against it is refused at exit 2 naming `severityLevels` until Hatsu adds `vulnEndpoint`, `severityLevels`, `severityFloor` and `timeoutSeconds` to it. Those values are Hatsu's policy to set, in the repin that retires the interim script. `nen/workflow.json`'s security review scope now claims `src/audit/**`.
