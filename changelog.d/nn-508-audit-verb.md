- New verb `nen audit deps` (zheref/nen#508): a directory's exact dependency pins, read from its lockfile and never by running its package manager, and with `--query` asked about at the OSV `querybatch` endpoint the caller's declaring contract names. `--contract` is an absolute path to a JSON file with a `dependencyAudit` object and `--row` names the row; Hatsu's `contracts/scans.json` `node` row is read unchanged. The row's `ecosystem` selects the reader: `npm` reads `pnpm-lock.yaml` (lockfileVersion 5, 6, 9), `yarn.lock` (berry and classic) and `package-lock.json` / `npm-shrinkwrap.json` (lockfileVersion 1, 2, 3); `SwiftURL` reads every `Package.resolved` at the root and inside an `.xcodeproj` or `.xcworkspace` bundle (formats 1, 2, 3), so the Swift procedure is now a verb, which can retire the hand procedure once Hatsu's `swift` row declares the four keys below. It is a port of Hatsu's interim `scripts/dependency_audit_resolve.mts`, and every lockfile case of that script's fixture but the one run on Hatsu's own tree passes here with the same exit code and verdict (the `audit-config:` lines now read "evidence for review"). Four exits: `0` clean (or resolved, without `--query`), `1` a finding at or above the row's `severityFloor`, an UNRATED id or an unqueried entry, `2` wiring (`nen exits audit` lists its own meaning of 2), `3` not scanned with the reason. A symbolic link, a truncated or unrecognised lockfile, a file over `maxLockfileBytes` (new, default 268435456), more than `maxEntries` entries or npm v1 nesting past `maxDepth` is not scanned. An entry from git, `file:`, a host off `registryHosts`, or a Swift pin on a branch or revision is unqueried and never clean. A pnpm entry is local or unqueried only by the keys of its own `resolution` map (a dependency named `is-directory` or a `# type: directory` comment no longer hides it), and a registry entry whose `resolved` or `tarball` URL names another name or version than the entry claims is unqueried. A malformed, non-JSON, oversized, failing, slow or unreachable OSV answer is not scanned, and so is a redirect, which is never followed or retried; a severity outside `severityLevels` counts as a finding. `vulnEndpoint` must end in `/`. It reads no environment variable of its own and forces certificate verification; the runtime's `fetch` honours the host's proxy variables and `NODE_EXTRA_CA_CERTS`, which USAGE documents as the host's network configuration. `--json` is `nen.audit.deps/v0.1`.
- Behaviour changes: `nen --help` lists 48 families, and `nen exits` gains two `audit deps` rows (`2` wiring, `3` not scanned). Hatsu's `swift` row as it stands names only `endpoint` and `ecosystem`, so `--row swift` against it is refused at exit 2 naming `severityLevels` until Hatsu adds `vulnEndpoint`, `severityLevels`, `severityFloor` and `timeoutSeconds` to it. Those values are Hatsu's policy to set, in the repin that retires the interim script. `nen/workflow.json`'s security review scope now claims `src/audit/**`, under a new criterion recorded in `review.$comment` for the maintainer's ruling: egress of the audited tree's dependency pins to a contract-named host.
