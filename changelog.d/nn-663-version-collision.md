- `nen/gates.json` takes an optional `version_collision` block (`version_file`, `version_pointer`, `shipped_paths`), the opt-in to a live plugin-version collision check ([#663](https://github.com/zheref/nen/issues/663)). It is read only at the pinned default-branch tip; the base's, the checkout's and a `--gates` copy only warn when they differ. A malformed block is refused by pointer: `version_file` must be one repository-relative path, `version_pointer` an RFC 6901 JSON pointer (never a pattern), and `shipped_paths` a non-empty list of unique globs in the `shu evidence` grammar.
- `nen pr version-collision <ref> [--target] [--pr] [--gh-repo] [--token-env] [--require-head] [--explain] [--json]` (contract `nen.pr.version-collision/v0.1`) is the read-only trusted-CI read of one pull request's collision: `not-applicable`, `clear`, `collision` (naming the version, every target tip that holds it and every other open same-repository pull request that proposes it from its own merge base) or `unknown` (naming every failed, capped, over-budget or moved piece of evidence). Exit 0 clear or not applicable, 1 collision or unknown, 2 usage, 8 head mismatch. Fork heads never block and are named in a warning.
- `nen pr ready` folds the same evaluator into its CON-32(a) `checks-green` row, read fresh on every call, so `watch until --pr`, `pr merge` and `loop slots --from-run` get it unchanged: a collision fails the row, an unknown on otherwise green checks makes it unknown (never ready), and `--explain` prints `└ version collision: …` with the policy source and read counts. `conjuncts[].versionCollision` and `meta.versionCollision` are additive to `nen.pr.ready/v0.1`. `nen pr next-blocker` does not evaluate the limb yet.
- A repository without the opt-in is unchanged: no extra read, no inventory call, and a byte-identical report.
