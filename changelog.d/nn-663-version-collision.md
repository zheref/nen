- `nen/gates.json` takes an optional `version_collision` block (`version_file`, `version_pointer`, `shipped_paths`), the opt-in to a live plugin-version collision check ([#663](https://github.com/zheref/nen/issues/663)). The copy at the pinned default-branch tip decides when it is readable and valid; no file there is no opt-in. When it cannot be read, parsed or validated, the repository counts as opted in only if that file's raw JSON or a copy at the base, in the checkout or under `--gates` shows a `version_collision` key; then the limb is `unknown`, naming what could not be read and where the opt-in showed. Otherwise the copies only warn when they differ. A malformed block is refused by pointer: `version_file` must be one repository-relative path, `version_pointer` an RFC 6901 JSON pointer (never a pattern), and `shipped_paths` a non-empty list of unique globs in the `shu evidence` grammar with at most four `**` segments.
- `nen pr version-collision <ref> [--target] [--pr] [--gh-repo] [--token-env] [--require-head] [--explain] [--json]` (contract `nen.pr.version-collision/v0.1`) is the read-only trusted-CI read of one pull request's collision. Its status is `not-applicable`, `clear`, `collision` or `unknown`. A collision names the version and each conflict by kind: `base` for a target tip that holds it, `unbumped` for a head that keeps its merge base's version after the base moved on, `peer` for another open same-repository pull request that proposes it from its own merge base. An unknown names every failed, capped, over-budget or moved piece of evidence. Exit 0 for clear or not applicable, 1 for collision or unknown, 2 for usage, 8 for a head mismatch. The open pull request inventory is one GraphQL query paged by cursor, so a pull request closed or reopened between page reads cannot shift another out of the walk. Fork rows never count as conflicts and are never compared for drift; they are named in a warning, and they still count toward the 10 × 100 inventory cap.
- `nen pr ready` folds the same evaluator into its CON-32(a) `checks-green` row, read fresh on every call, so `watch until --pr`, `pr merge` and `loop slots --from-run` get it unchanged. A collision fails the row, and an unknown on otherwise green checks makes it unknown (never ready). `--explain` prints `└ version collision: …` with the policy source and read counts. `conjuncts[].versionCollision` and `meta.versionCollision` are additive to `nen.pr.ready/v0.1`. `nen pr next-blocker` does not evaluate the limb yet.
- Without the opt-in nothing changes: `nen pr ready` reads nothing more and its report and exit code are byte-identical, including when the default-tip `nen/gates.json` cannot be read, parsed or validated and no copy shows the opt-in (then `nen pr version-collision` answers `not-applicable` with a warning).
