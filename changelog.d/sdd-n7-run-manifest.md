- `nen run start|append|park|verify|budget` keep a batch run's manifest (contract `nen.run/v0.1`, Hatsu ruling HR-5) at `<git-common-dir>/.nen/runs/<run-id>.json` (git asked with an inherited `GIT_DIR`, `GIT_COMMON_DIR` and `GIT_WORK_TREE` dropped): `start --target` records the run's repository and launch-time idle answers (the same answers again is the resume, other answers or another repository exit 1); `append` reads each PR live in that repository and records its base, head branch and head commit, refuses at exit 1 a PR created before the run started, takes `--issue` (null for an integration or release PR), is idempotent on the same facts, `updated` on a moved head or base, exit 1 on another issue, kind or effort; `park` records `parked[] { issue, row, at }`, HR-5's park state; `verify --target` (which must name the run's repository, exit 2 otherwise) reads every recorded PR live and reports open, merged and closed-unmerged with the unmerged list, exit 1 and `unmerged: unknown` when any PR could not be read; `budget` compares wall-clock minutes since the run's start and the efforts' recorded tokens against `--max-minutes`/`--max-tokens` (or `idle.budget`), reports the efforts' own minutes as `effortMinutes`, and fails closed -- `unevaluated`, a claim refused, exit 1 -- when a token figure is missing (an entry recorded `--not-reported`, a delivery PR with no effort or no ledger); `--claim` refuses at exit 1 once either ceiling is reached. `start`, `append` and `park` take `--dry-run`.
- `nen loop slots --from-run <run-id> --target <owner/name>` builds the efforts document from the manifest and live reads -- PR state, `nen pr ready` in process, a stop marker in the PR's worktree -- so no field is caller-typed; anything unread keeps its slot held and is named.
- `nen wc overlap --efforts <a,b,...> --repo <path> [--base <ref>] [--always-overlaps <paths>]` computes file disjointness from each effort's merge-base diff, counting `nen/workflow.json`'s new `alwaysOverlaps` list (validated by a `schema check` row) as every effort's: `disjoint` (exit 0), `stack(<order>)` when the overlapping efforts' branches already chain, `overlap(<paths>)` or `unknown` (exit 1).
- `nen stage check --exclusive --target <owner/name> (--issue <N> | --issues <n,...>)` exits 1 when an issue carries two stage-family labels, the family read from `nen/labels.json`; an unread issue is exit 1, never exclusive, and a taxonomy with no stage family is exit 2 naming the file.
- `nen loop slots` reads `idle.localSlotFrees` under a declared idle profile before `monitor.localSlotFrees`; stating both with two values is refused, and `schema check`'s `#idle` row warns on an idle key nen does not read.
- `nen parse futon` reads an optional `--idle` flag of the scope (HR-5), reported as `idle` in both outputs.
- `nen parse izanami` classifies the new verbs: `run start`, `run append` and `run park` mutating (read-only under `--dry-run`); `run verify`, `run budget`, `wc overlap`, `stage check` and `loop slots --from-run` read-only.
- Behaviour changes: `nen parse futon --json` gains an `idle` key (`false` unless `--idle` was typed), `--idle` after `then` -- previously prose -- is now refused at exit 2 with the line moved, and an unquoted label selector whose last word is ` --idle` (or a scope whose first word is `--idle `) now reads as the flag rather than as part of the label; quote such a label to keep it. `nen run --help` documents five subcommands where it documented one, and `nen run rerun-failed` now refuses the manifest verbs' flags at exit 2. `nen wc` and `nen stage` gain one subcommand each and refuse the new flags on their other subcommands. `nen loop slots`'s usage line names `--from-run`; a call with neither `--efforts` nor `--from-run` says so at exit 2 as before.
