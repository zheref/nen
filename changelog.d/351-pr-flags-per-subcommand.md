- **pr** — every `pr` subcommand now refuses, at exit 2 and before any `gh` call, each flag it does not read, naming the subcommands that do read it (`--from` names `pr threads settle`; `--reviewers` names `pr ready` and `pr next-blocker`). One per-subcommand table in `src/pr/command.ts` replaces the family's spread of `pr ready`'s flags and the one-flag-at-a-time refusals, and the parser's flag set is derived from it. A `--token-env` refusal says which credential that subcommand actually runs on. `pr --help` and the reference say an unknown flag is unknown per subcommand (refs #351).
- **Consumer note** — an invocation that carried a flag its subcommand never read now exits 2 where it used to exit 0 with the flag ignored: `--token-env` or `--gh-repo` on `edit-body`, `request-reviews`, `threads`, `open`, `retarget`, `fetch`, `next-blocker` or `cascade-main`, or any other family flag outside the subcommand's own set (for example `pr ready --policy`). Remove the flag; nothing it named was ever applied.
