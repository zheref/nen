- The private-name guard matches a private repository named after an ORDINARY WORD only in repository-shaped forms — `owner/name`, `name#N`, `owner/name#N` and a URL path naming it — never as a bare word (zheref/nen#535, the maintainer's ruling of 2026-10-25). The decision is an exact, case-insensitive match of the whole name against a word list embedded in the binary (`src/issue/ordinary-words.json`: 10,737 words from SCOWL 2020.12.07, Kevin Atkinson's permissive licence, recorded in the file and in `docs/USAGE.md`), so it reads no host dictionary and answers the same everywhere; a hyphenated, dotted or otherwise multi-word name is never ordinary and keeps the bare-word match. Every guarded verb shares it: `issue file|comment|edit-body|consolidate-close`, `idea file`, `pr open|edit-body|threads reply|settle|ledger post`, `wake fire|verify` and the release publisher, whose v0.28.0 notes it refused at exit 4 for nen's own `stop` flag and schema id. Behaviour changes: a bare use is no longer a hit but a stderr line `<verb>: not matched: <field>:<line>: private repository #<k> (ordinary word: matched only as owner/name, name#N or a URL)`; `--json`'s `privateNameCheck` gains `ruled` (`[]` when nothing was checked), and every hit gains `form` (`bare` | `repository-shaped`) and `class` (`ordinary-word` | `null`), so a caller comparing a hit or the verdict with `toEqual`-style exact equality must add them. The ignore file, the committed named list, `--skip-private-name-check` and every exit code are unchanged.
