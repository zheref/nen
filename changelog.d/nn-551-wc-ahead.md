- New verb `nen wc ahead --repo <path> --of <reviewed-head> [--head <ref>] [--json]` (zheref/nen#551): the commits and diff stat a branch carries beyond a NAMED reviewed head, read from the clone with no fetch, so Hatsu's `en` and `sharingan` no-op sync guard stops running a raw `git rev-list --count <reviewed-head>..HEAD`. Four verdicts, each with its own exit code: `ahead <n>` (exit `0`, with the reviewed head's full id and `files`/`insertions`/`deletions` from `git diff --numstat` between the two trees), `even` (exit `3`: the head is the reviewed head, nothing new to review), `diverged` (exit `1`: the reviewed head is not an ancestor after a force-push, a rebase or a reset, and every count is `null`), and `unreadable` (exit `2`: the clone does not hold `--of` or `--head` as a commit, the short id is ambiguous, a shallow clone answers "not an ancestor", or git could not answer; the verdict is still printed and is never zero). Only `even` means nothing new: `diverged` and `unreadable` need their own branch in a caller. Every git call runs with `GIT_NO_LAZY_FETCH=1`, so a partial clone never fetches; one missing the blobs the line counts need keeps its count and file count with `insertions`/`deletions` `null` and `reason` saying why. `--json` keys: `verdict`, `of`, `reviewedHead`, `head`, `headSha`, `ahead`, `files`, `insertions`, `deletions`, `reason`. izanami classifies it read-only.
- Behaviour changes: USAGE and the README count 173 verbs, `nen exits` gains two `wc ahead` rows (`2` unreadable, `3` even), and every other `wc` verb now refuses `--of` and `--head` by name at exit `2`.
