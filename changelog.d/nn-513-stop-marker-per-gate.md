- `nen stop --mark` keeps one marker per gate (zheref/nen#513): besides `.nen/last-stop.json` it writes `<git-common-dir>/.nen/marks/<effort>/<gate>.json`, contract `nen.stop.mark/v0.3` (every v0.2 key plus `effort`), so several gates marked in one run no longer replace each other and a worktree removal keeps them. `--effort <id>` (with `--mark`) names the stop's effort.
- `nen stop list [--json]` (`nen.stop.list/v0.1`) prints every unrung marker with its gate, effort and instant, and an older single `.nen/last-stop.json` as `legacy` when no per-gate marker is the same stop. A marker file it cannot read is exit 1, listed under `unreadable`.
- `nen stop clear --gate <g> [--effort <id>]` removes only that gate's marker; `clear --all` removes every marker, an unreadable marker file included (named as such); a bare `clear` still removes `.nen/last-stop.json`, and now also its per-gate twin.
- A per-gate marker whose `.nen/last-stop.json` twin a hook removed itself (rang and consumed, as Hatsu's stop-bell does) is not listed. The next `--mark` deletes it, and `<marks>/.latest.json` records which marker the single file twins. `stop clear --gate none` clears a stop marked with no gate.
- Backward compatible: `.nen/last-stop.json` is written byte for byte as before and `stop show` still reads it, so a Stop hook reading the single file rings for the latest stop as it did. Behaviour changes: `--mark`, `stop list` and every `stop clear` form now spawn `git rev-parse --git-common-dir`; `--mark` writes a second file, and is exit 2 where git refuses for a reason other than "not a git repository".
