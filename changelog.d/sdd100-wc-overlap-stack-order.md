- `nen wc overlap` returns `stack(<order>)` whenever efforts share a path (zheref/nen#488 AC-2), one stack per connected group of sharing efforts: A and B sharing `p` beside C and D sharing `q` read `stack(A <- B; C <- D)`. Each group's order is the one git holds when its branches chain (`source: "chain"`), else the order the caller listed `--efforts` in, the order its epic names (`source: "given"`, or `"ancestry-unread"` when git could not say). An effort that shares no path is left out. Two efforts that both touch `plugin.json`, touched or declared always-overlapping, now stack.
- `nen wc overlap --declared <file>` reads each effort's declared paths before authoring (AC-1): a JSON object of effort -> repository-relative paths, standing in for a diff that cannot be read yet and added to one that can. Each effort row gains `sources` and keeps the diff's `unreadReason` when declared paths stood in (AC-3). An unreadable or malformed `--declared`, or an empty path list, exits 2.
- **Behaviour change:** the `overlap(<paths>)` verdict is retired. Efforts that overlap and do not chain read `verdict: stack(...)` and an `order …: given (...)` line at the same exit 1; `--json` adds `stacks: [{ efforts, source }]`. A caller that branched on `verdict == "overlap"` reads `stack` with `stacks[].source: "given"` instead.
