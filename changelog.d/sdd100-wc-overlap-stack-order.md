- `nen wc overlap` returns `stack(<order>)` whenever efforts share a path (zheref/nen#488 AC-2): the order git holds when the branches chain (`stackSource: "chain"`), else the order the caller listed `--efforts` in, the order its epic names (`stackSource: "given"`). Two efforts that both touch `plugin.json`, touched or declared always-overlapping, now stack.
- `nen wc overlap --declared <file>` reads each effort's declared paths before authoring (AC-1): a JSON object of effort -> repository-relative paths, standing in for a diff that cannot be read yet and added to one that can. Each effort row gains `sources` and keeps the diff's `unreadReason` when declared paths stood in (AC-3). An unreadable or malformed `--declared` exits 2.
- **Behaviour change:** the `overlap(<paths>)` verdict is retired. Efforts that overlap and do not chain read `verdict: stack(...)` and `order: given (...)` at the same exit 1; `--json` adds `stackSource`. A caller that branched on `verdict == "overlap"` reads `stack` with `stackSource: "given"` instead.
