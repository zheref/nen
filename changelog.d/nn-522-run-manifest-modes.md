- Run manifest modes and dry forms (zheref/nen#522): every write of the `nen.run/v0.1` manifest -- `nen run start`, `append`, `park`, `import` and the one-time move from the legacy `<git-common-dir>/hatsu/runs/` -- now lands it at `0600` in a `0700` directory (the directory created at `0700`, the document written to a temp file created exclusively at `0600` and renamed over), and the modes are read back and printed: `mode: file 0600, directory 0700`, with `(narrowed: ...)` when a write narrowed a wider one, and `mode` `{ verdict, file, directory, repaired, reason }` in `--json` (null when neither the plan nor a legacy move writes). Where a mode cannot be set -- a `win32` host, a failing `chmod`, a read-back that is not `0600`/`0700` -- the write stands and the verb says `mode: not set (<reason>)`, verdict `not-set`, rather than claiming the mode. `nen run verify` and `nen run budget` take `--dry-run`: a manifest still at the legacy path is read in place and the move printed on stderr (`would move run manifest ...`), nothing moved. The `--dry-run` of `start`, `append`, `park` and `import` creates no directory and moves no legacy manifest, and prints `mode: would set file 0600, directory 0700`.
- Behaviour changes: manifest modes are now set and repaired -- a manifest an earlier build left at the umask's `0644` under `0755` is narrowed to `0600` under `0700` on its next write, and said so. `--json` of `run start`, `append`, `park` and `import` gains a trailing `mode` key, and their text output a trailing `mode:` line when they write or would write. `--dry-run` of `start`, `append`, `park` and `import` no longer moves a legacy-path manifest (it used to, before planning the dry write). `nen run verify --dry-run` and `nen run budget --dry-run` are accepted where they used to be refused at exit 2 as another subcommand's flag. `nen loop slots --from-run` no longer moves a legacy-path manifest: it reads it in place and names the `nen run verify --id <id> --target <owner/name>` line that moves it on stderr. A manifest path, a legacy manifest or a runs directory -- or any component of it below the git common dir, such as `.nen` -- that is a symbolic link (or not a regular file) is now refused at exit 1, naming it, by every run verb that reads or writes the manifest and by `loop slots --from-run`, where it used to be read, moved and `chmod`-ed through the link; `nen run record read` likewise answers `could-not-read` for a record directory that is a link, as `record write` already refused one, and both now check every component of the record directory below the state home (`hatsu` as well as `hatsu/specs`). When a verb moves a legacy manifest, `--json` `mode` carries the move's modes -- alone when its plan then writes nothing (`existing`, `unchanged`), combined with the plan's when it writes too -- instead of null or the second write's alone. izanami (`nen parse izanami`) now classifies bare `nen run verify` and `nen run budget` **mutating** and only their `--dry-run` forms read-only, since the bare forms can make the legacy move.
