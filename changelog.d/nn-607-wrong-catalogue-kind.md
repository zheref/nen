### Changed

- A `--catalogue` of the other kind is now named as that, in both directions (zheref/nen#607). `nen pr body-check`, `nen pr converge` and `nen pr merge` read the issue-sections catalogue (as do the issue verbs' `--requirements-from`), and `nen pr sections resolve` / `family` read the PR-sections catalogue. Handed a file whose top-level `contract` declares the other kind (`<namespace>.pr-sections/<version>` or `<namespace>.issue-sections/<version>`), each now refuses before reading any field with "the wrong kind of catalogue was passed", the contract it read, the kind it expects, and the verbs that take the file it was given. Before, the first inner field that did not fit was reported (`section 'verify' needs 'title'`, `at sections, expected an array`), which read like a version incompatibility.
- Only the message changes. No exit code moves: the issue-sections readers still refuse at exit 2 and the two `pr sections` actions at exit 1. A catalogue that declares no `contract`, or one naming neither kind, is read field by field exactly as before, and so is a malformed catalogue of the right kind.
