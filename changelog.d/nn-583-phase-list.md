- `nen phase list [--repo <path>] [--since <minutes>] [--json]` (contract `nen.phase.list/v0.1`) lists every effort that has a phase ledger, one row each (zheref/nen#583): the effort id decoded from the ledger's file name (the inverse of the one encoder, refusing a name it could never have written), the ledger's newest phase -- the last entry of `phases[]`: `begin` appends, and `nen pr ledger read --restore` writes a whole `phases[]` back in its original order (the file's modification time is then the restore's) -- with its `startedAt`, `endedAt` and `exitCode`, and the file's modification time, newest first with ties by effort id. `--since <minutes>` keeps only ledgers modified within that window of the invocation's clock; anything but a positive whole number is exit 2.
- It reads every location `nen phase show` reads -- the durable `<git-common-dir>/.nen/phases/` and every checkout's older `.nen/phases/` -- and lists each effort once: a copy in more than one place is one `conflict` row naming every copy, as `show` refuses it. A ledger that cannot be read (bad JSON, another or a newer contract, an effort its file name does not decode to, a link or other non-regular file -- opened once with `O_NOFOLLOW | O_NONBLOCK` where the platform has them -- a file over 8 MiB, an unreadable file) is one `unreadable` row with its file name and reason, and the other rows still print at exit 0; no ledger directory is an empty list. The verb is read-only: it moves no older copy, writes nothing, takes no ledger lock and creates no directory.
