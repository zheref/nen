- `nen pr retarget`, `nen pr cascade-main` and `nen run rerun-failed` take `--dry-run` (Hatsu SDD plan N6, finding D6): each prints the exact `gh`/`git` call(s) as `would run:` lines and spawns nothing, not even a read, at exit 0. `cascade-main --dry-run` prints fetch, merge and (unless `--no-push`) push; whether the merge would conflict is not known without merging. izanami keeps all three `mutating` in every spelling, fail-closed.
- `nen phase begin --resume`: an entry already open with the same `--phase` name is continued -- the instant appended to a new, additive `resumedAt` array, every other field kept -- instead of refused (`end` still measures from the original start; `show` prints the resumes); with nothing open it begins a fresh entry; with a differently named phase open it is refused at exit 2, writing nothing. The ledger contract stays `nen.phase.ledger/v0.1`.
- A new test holds USAGE's `--dry-run` discipline table to the registry: every row names a preview flag, and every verb it names is registered and accepts that flag (per subcommand for `pr`).
- Behaviour changes: `nen pr open` returns a pull request already open for the head **against the same `--base` and at the head commit this checkout pushed** as `opened: existing <owner/name>#<n>: <url>` at **exit 0** (`existing: true`), so a retry after a timeout never opens a second one and never reads as a failure (with `--assignee`, the adopted pull request's assignees are read back and one missing is exit 1); consumers that read exit 1 as 'already open' (Hatsu `shibari`) must read `existing` instead; it was exit 1 before. Against another base, at another head commit (`--head` matches a branch name from any fork), or when the open pull request's number, url, base or head commit cannot be read, it stays exit 1, nothing opened or retargeted. The `gh pr list` it asks now reads `number,url,baseRefName,headRefOid`. `nen pr retarget --json` and `nen run rerun-failed --json` gain `dryRun` and `command` after `ok` and `message`; `nen pr cascade-main --json` gains `dryRun` last. `nen phase begin` on a phase already open now names `--resume` in its refusal.
- Behaviour changes (zheref/nen#419): `nen parse <skill> --grammar` refuses, at template time with exit 2 and a rewrite in the message, any slot after the first that no literal word or symbol introduces -- `<a> <b>`, `<a> <b:x|y>`, `<a> [<b>]` and `<a> {x} <b>` -- which before parsed at `ok: true` while never capturing or checking the later slot. `<a>`, `<a>@<b>`, `<a> then <b>`, `<a>{+}` and alternations `<a:..>|<b>` are unchanged. A template refused this way never checked its later slot; consumers should re-check every `--grammar` at the repin (no Hatsu template uses the refused shape).
