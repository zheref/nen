- `nen labels sync` reads `nen/labels.json` from a branch before it merges (zheref/nen#591): `--ref <ref>` reads the file as a branch, tag or commit in the `--repo` checkout has it (`git cat-file blob <ref>:nen/labels.json`, no fetch), and `--working-tree` names the checkout's own file explicitly. Both modes are a dry-run diff by default and sync only behind the new `--apply`; stderr opens with `source: <where> (dry run; --apply syncs)`. Usage errors (exit `2`, before any read): `--ref` beside `--working-tree`, `--apply` beside `--dry-run`, `--apply` without either mode, and a ref that opens with `-` or carries `:` or whitespace. An unreadable ref or an invalid file there exits `1` before GitHub is read. The plain form is unchanged: it still syncs unless `--dry-run`.
- Behaviour changes: a dry-run `would update` line from `labels sync` (and `classify install --sync`, which shares the diff) now ends with the remote's current values of the fields that differ — `(was: color #000000)`, `(was: description "old")` — and `classify install --sync`'s default-branch refusal names `nen labels sync … --ref <branch>` as the way to diff an unmerged declaration.
