- `nen classify install` now installs the `model/` label family hatsu:direct applies (zheref/nen#590). The classification taxonomy gains an optional root `families` block: install-only label families with the axis shape (`prefix`, `color`, `keys` with `key`, `title`, `description`), keyed by a kebab-case name that is not an axis. `classify install` compares, writes (`--write`) and syncs (`--sync`) every family label beside the two axes', with the same present/drift/absent report, and lists a declared label wearing a family prefix but an uncarried key as `foreign`, never touched. `classify labels` prints the family labels (its count line adds `, <n> <family>`; `--json` adds a `families` block and a `family` field per label, `axis` `null` on a family label), and `classify status` holds GitHub and the declaration to the family labels too. A family is never classified on: `status` and `apply` still read exactly the two axes, so an issue with no `model/` label stays classified. A family named like an axis, one whose prefix overlaps an axis's or another family's, or one with no keys is refused by pointer. A taxonomy without `families` reads exactly as before.
- Behaviour changes: `classify labels --json` adds the `families` key and a `family` field on every label row; the governance taxonomy must declare `families.model` (zheref/hatsu `contracts/classify.taxonomy.json`) before a consumer's install carries the five `model/` labels.
