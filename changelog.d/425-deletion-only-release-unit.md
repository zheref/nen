`release.unitPaths` accepts `{ "path": "changelog.d/", "deleteOnly": true }` to permit fragment deletions while refusing additions, edits and renames by filename, including renames into or out of the prefix. Missing or unknown GitHub statuses fail closed, and overlapping broad bounds cannot waive deletion-only restrictions. Schema checks validate and count the new entries; unit-check reports expose an additive `deletionOnlyPaths` field. Nen declares its own fragment prefix deletion-only; this policy must land before the next release proposal because bounded merges read their base policy. Consumers can adopt this new entry kind with the next Nen minor; no provisioning is needed. Existing string, JSON-key and text-line bounds remain supported. (Refs #425)
