- New verb `nen shu typecheck [--lane <name>] [--dry-run] [--json] [--stream] [--heartbeat <s>]` (zheref/nen#588): runs the lane's declared static type check — `project.verbs.<lane>.typecheck` in `nen/contract.json`, single-step or `steps` — through the same executor as `shu lint`, per lane: exit `0` when it passes, `1` when a step fails (the checker's own code on the step line). A lane that declares none is exit `4` naming that exact pointer; nen never falls back to `build` or to a checker it guessed. `--json` is the shared run report with `contract: "nen.shu.typecheck/v0.1"`; izanami classifies it `dry-run-gated`; a `stall` guard is accepted, as on `lint`.
- Reference pack: `typecheck` joins `profiles/index.json`'s verbs (and `commandVerbs`), so every profile answers it. `nextjs` seats `{pm} -r exec tsc --noEmit`, the line both observed repositories' CI runs (cited in the profile's `source`); `detect` proposes it only where the lane's `package.json` spells the line out verbatim as one of its scripts (`tsc` ships under the `typescript` package name, which detect does not map to the program). `expo` (TypeScript configured, never run), `gatsby` and the four compiled stacks are `unsupported`. `docs/STACK-MATRIX.md` regenerated.
- Behaviour changes: every `shu` refusal for an undeclared verb now names the exact pointer (`nen/contract.json at project.verbs.<lane>.<verb>`) instead of the lane's verb map; USAGE and the README count one more `shu` verb; nen's own contract declares `typecheck` on the `nen` lane.
