- `nen/workflow.json` gains `commits.stripInjected` (zheref/nen#594): an OPT-IN list of trailer keys, empty by default — the strip is OFF until a repository lists a key, and every listed key must be one the policy refuses (a key nothing refuses, or one it admits, is refused by pointer) — that the `nen scaffold init` commit-msg hook may remove from a message's trailer block when a hook added them inside a commit `nen commit write` or `nen wc squash` started — Cursor's cloud agents append `Co-authored-by:` in a `prepare-commit-msg` nobody can switch off, and until now no nen-scaffolded repository could take a commit from one. The strip runs only when `NEN_COMPOSED_TRAILER_KEYS` is set (the two verbs set it on their child `git commit`), never touches a key the composed message carried, never admits a refused key, never amends, and reports every removal on stderr and in `<git dir>/nen-stripped-trailers.<run id>`, the run id a fresh random hex the verb sets in `NEN_STRIP_RUN` (neither variable is ever exported by hand; a leaked one still strips, says so, and records nothing). The spaced `Key : value` form is stripped too; a longer key such as `Co-authored-by-bot` is not. The step is locale-proof (no bracket range or class; `tr` and `awk` under `LC_ALL=C`), and a CRLF message is handled with its line endings left to the platform's awk and git's cleanup. Without the opt-in, docs/USAGE.md now says plainly that a hook-injected refused key is a refusal with no sanctioned way around it, pointing to zheref/hatsu's `docs/AGENT-ATTRIBUTION.md` for the stop.
- Behaviour changes: `nen commit write` and `nen wc squash` gain exit `4` — committed, and the hook stripped a hook-injected key — with `3` (a refused key still on the commit) winning over it and it over `0`; their `--json` gains `stripped: [key, ...]`, appended last (`null` on a dry run, `[]` when nothing was stripped). Exit `4` is a COMMITTED outcome: callers treat it like `0` and `3` and never retry, and the Hatsu repin updates its commit steps to read it so. Both now ask `git rev-parse --git-dir` before the commit and run it with `NEN_COMPOSED_TRAILER_KEYS` and `NEN_STRIP_RUN` set. A commit the hook refused for a listed key adds a hint that the hook may predate `commits.stripInjected`, and the exit-3 line for a hook-added key names the opt-in as a second remedy. Generated hooks are unchanged until a repository lists a key and regenerates with `nen scaffold init … --force`: with the list empty the hook is byte-identical, so `scaffold init` keeps reporting it `unchanged`. `templates/workflow.json` writes `"stripInjected": []` into a fresh policy.
