- `nen changelog fragment-required` reads the first versioned section at level 2 or 3, by its level and `vX.Y.Z` whatever its suffix, so a release move into `## vX.Y.Z — <date>` (nen's form) or `## vX.Y.Z — <theme>` (Hatsu's) is recognised, not only `### vX.Y.Z`. `collate` writes those forms and copies fragment lines verbatim; a hand-written `##` section's `###` subsections count toward its entries too, up to the next heading at its own level or higher. Before, such a release PR had no head version and was `required` at exit 1 (Bugbot on zheref/nen#527).
- `fragment-required`'s release-move reader shares `changelog completeness`'s heading predicate (zheref/nen#528): a pre-release suffix is part of the version, so `v1.2.0-rc.1` → `v1.2.0-rc.2` is a move; a `— unreleased` heading is not dated and is skipped, so the PR that only dates it is the release move; and a section's entry count stops at the next version heading at level 2 or 3, so a `### vX.Y.Z` below a `## vX.Y.Z` release no longer adds the previous release's bullets.
- Compatibility: a `##`-form changelog that read as having no version now reads one, so `fragment-required` can answer `release-move` where it answered `required`. `###`-form changelogs read as before.
- `nen canon lint --rules <path>` reads a caller-named contract whose real location is outside `--root` as named (a relative path resolves against `--root`), for the sibling-checkout CI form that puts the trusted revision beside the head. This departs on purpose from the ported Hatsu guard, which holds `--rules` inside the root. A `--rules` path that reaches into the root under any spelling (its realpath, a symlinked root, an outside link pointing in; zheref/nen#528), and `canon.lint.rules` always, stay held to SEC-7: a symlink there leaving the root is still exit 2 (Bugbot on zheref/nen#527).
- `nen canon lint --help` says when an advisory finding prints: one line each under `--base` only; a whole-tree run, `--base-baseline`'s CI form included, carries them in `--json`'s `advisory[]`. The behaviour is unchanged and matches the guard it ports (Bugbot on zheref/nen#527).
