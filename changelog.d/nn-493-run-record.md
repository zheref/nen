- `nen run record read|write --schema <id> --id <run-id> [--from <file>] [--dry-run]` (zheref/nen#493, AC-11): a caller's resumable run record, validated against a schema shipped as data (`hatsu.spec.run/v0.1`, Hatsu's `dowsing-chain` record) and kept at `${XDG_STATE_HOME:-$HOME/.local/state}/hatsu/specs/<run-id>.json`. The run id is matched whole against the schema's pattern before any path is built; the record's `schema`, `caller` and `runId` are checked before its fields; every row value is typed (codes, shas, statuses, counters); a relative `XDG_STATE_HOME` is ignored for `$HOME/.local/state`; a write is the whole document through a temp file created exclusively at `0600` in a `0700` directory that is never a link or another user's, then a rename, and a failed write or an unreadable `--from` is `could-not-read`. Verdicts `valid` · `written` · `would-write` · `absent` · `invalid` · `could-not-read`. It sits beside the batch manifest (`run start|append|…`), which stays under the git common dir.
