- `nen loop slots --from-run` counts claimed efforts that have no pull request yet (zheref/nen#521). The run manifest may carry an optional `claims[]` `{ issue, branch, at }`; every claim whose issue no delivery PR row names (by issue, or by the claim's branch) is a local effort with `pr: null` and id `<issue> (claimed)` that holds a slot, so a batch can no longer launch past its budget in the window between claiming an effort and opening its PR. The latest claim per issue decides: a `parked[]` row for that issue at or after it frees the slot (`fromRun.parkedClaims`). `fromRun` gains `claims` (`read`, `not-recorded`, `unread`), `parkedClaims` and `claimsUnread`. Two references name one issue only by an equal `owner/name`, an equal code, or a code that `--repo`'s `nen/repos.json` assigns the run's repository, never by number alone (`NN#5` and `HA#5` are two efforts). Claim rows that will not read are reported, the local plane reads `free: 0` (forced, so `occupied + free` may be below `cap`) and `binding: true`, and the exit is 1: could not look, never nothing claimed. A claim's `at` must be an ISO-8601 instant by shape, not merely something `Date.parse` accepts. No verb writes `claims[]` yet (zheref/nen#564); `nen run append` and `nen run park` carry a stored value verbatim through every rewrite. A claim merged locally into the integration branch with no PR still holds under `--from-run` until a recorded fork commit can prove the merge (zheref/nen#565).
- Behaviour changes: in `nen loop slots`, a local effort with no PR and `merged: true` now frees its slot under every `localSlotFrees` rule (a local integration with no sub-PR, Hatsu HR-353), where `ready+prompted` and `stacked-open` used to hold it as `authored locally, no PR yet`. An `--efforts` file that relied on such a row holding must drop `merged` from it. A run manifest's `claims` key, which this build used to drop on the next rewrite, is now kept. A manifest whose `parked[].at` parses with `Date.parse` but is not an ISO-8601 instant by shape (e.g. `"1"`) is now refused as unreadable; every nen writer stores `toISOString()`, so only a hand-edited manifest is affected.
