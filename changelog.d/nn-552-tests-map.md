- New verb `nen tests map` (zheref/nen#552; Hatsu assessment finding D8, scorecard SDD-19 *tests first*): each acceptance criterion of an issue body with the tests whose names carry its id, and each criterion with none. Read-only over local files: `--issue-body <file>` read in `nen issue criteria`'s grammar (`--requirements-from` takes the prefix and acceptance section from the catalogue), and `--test-report <file>[,<file>...]` read through `shu test-report`'s parsers (JUnit XML, JSON assertion-results, xcresult summary), so no runner is named and nothing is run. A test names a criterion by carrying `AC-3`, `#552/AC-3`, `NN#552/AC-3` or `zheref/nen#552/AC-3` in its name or suite; `--issue <ref>` anchors qualified tokens, and one naming another issue is listed as foreign. Every criterion is listed with its test count, `0` included (`mapped` · `unmapped`); a test naming an id the issue does not carry is `unrequested` by name. `--require-red` reads the one report as the checkpoint before the change (met only when every test naming a criterion failed); `--before-report <file>[,<file>...]` reads a recorded red run beside the green one, and each criterion reads `red-first`, `green-only`, `failing` or `untested`. A body with no criterion row is `not-verifiable`, and an unreadable body or report is `could-not-read` with the reason, never an empty map. Exits `0` every criterion met in the mode, `1` otherwise, `2` usage. `--json` is `nen.tests.map/v0.1`.
- Behaviour changes: `nen --help` lists 49 families. The Hatsu half — its authoring phase running the red checkpoint per criterion and recording it in the phase ledger — is Hatsu prose, owed after this verb releases and a repin.
