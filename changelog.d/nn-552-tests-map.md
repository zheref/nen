- New verb `nen tests map` (zheref/nen#552; Hatsu assessment finding D8, scorecard SDD-19 *tests first*): each acceptance criterion of an issue body with the tests whose names carry its id, and each criterion with none. Read-only over local files: `--issue-body <file>` read in `nen issue criteria`'s grammar (`--requirements-from` takes the prefix and acceptance section from the catalogue), and `--test-report <file>[,<file>...]` read through `shu test-report`'s parsers (JUnit XML, JSON assertion-results, xcresult summary), so no runner is named and nothing is run. A test names a criterion by carrying `AC-3`, `#552/AC-3`, `NN#552/AC-3` or `zheref/nen#552/AC-3` in its name or suite (`AC-1/AC-2` is two tokens); `--issue <ref>` anchors them, and a qualified token naming another issue, or a bare one in a test that names only other issues, is listed as foreign. Every criterion is listed with its test count, `0` included (`mapped` · `unmapped`); a test naming an id the issue does not carry is `unrequested` by name. One red bar serves both red readings: every test naming the criterion failed in the red run. `--require-red` reads the one report as the checkpoint before the change; `--before-report <file>[,<file>...]` reads a recorded red run beside the green one, and each criterion reads `red-first`, `green-only`, `failing` or `untested`. A red run whose test file failed to load (a failed row named for the file) is attributed to every after test of that suite as `load-failed`; under `--require-red` those criteria read `untested` (zheref/nen#559). A body with no criterion row is `not-verifiable`, and an unreadable body or report is `could-not-read` with the reason, never an empty map. Exits `0` every criterion met in the mode, `1` otherwise, `2` usage. `--json` is `nen.tests.map/v0.1`.
- Behaviour changes: `nen --help` lists 49 families. `shu test-report` (and every reader of its parsers) now reads an assertion-results file that failed with no assertions as one failed row named for the file, where it read nothing, so a suite whose files failed to load is no longer a green run with zero tests. The three test-report formats look outcome words up in their tables' own keys only, so `<constructor/>` or `"status": "constructor"` no longer replaces a failure. The XML reader shares each element's ancestor chain instead of copying it and refuses nesting deeper than 256 levels; a test report over 64 MiB is refused before it is read. The Hatsu half — its authoring phase running the red checkpoint per criterion and recording it in the phase ledger — is Hatsu prose, owed after this verb releases and a repin.
