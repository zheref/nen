- Epic-scoped criterion ids (zheref/nen#519): `nen issue criteria`, `nen issue body-check` and `nen pr converge` (and `pr body-check --criteria`/`--criteria-from`, `pr merge --delivery`) now share one criterion id grammar, and Akatsuki's `- AC-12-001: …` rows are criteria with their whole id -- `AC-12-001`, never truncated to `AC-12` -- where they used to be listed as unrecognised and the issue read not verifiable. A verify row `<CODE>#<N>/AC-12-001` matches that criterion and `<CODE>#<N>/AC-12` does not. With no catalogue the id is one number or several joined by hyphens; with a catalogue (`--requirements-from` / `--catalogue`) the shape is the group its `rows.acceptance.pattern` opens right after the prefix, never a binary default, so Hatsu's `^- AC-([0-9]+): …` keeps reading `AC-{n}` only. The bold `- **AC-1**:` form, `AC-01` read as `AC-1`, and the `SC-`, `AS-`, `OQ-` rows are unchanged.
- Behaviour changes: a `hatsu.issue-sections/v1` catalogue whose `rows.acceptance.pattern` opens no group right after `<ID>-` is now refused at exit 2 naming that field, where its acceptance id used to be read as `<ID>-<n>` regardless. A list row such as `- AC-1-2: …` that used to be unrecognised (blocking `pr converge`) is now the criterion `AC-1-2` when no catalogue is given. A criterion's `--json` `number` is its id's last number (`AC-12-001` is 1); rows are matched by `id`. `--criteria AC-01` is now read as `AC-1` where it used to be refused at exit 2.
