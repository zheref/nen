- **issue, idea, pr, wake, release** — the private-name guard #329 put on `issue file`, `issue comment` and `issue edit-body` now runs before every write of caller text to GitHub: `issue consolidate-close` (each child's `--close-comment`/`--close-comment-map` text, before the attach), `idea file` (title and body), `pr open` (title and body, before any other call), `pr edit-body` (body, after the certifying read), `pr threads reply` and `pr threads settle` (every reply body, before the walk), `wake fire` (`--comment`, before the label is touched), `wake verify` (`--now` and the two markers, before the first read) and nen's own `src/dev/release-publish.ts` (release title and notes, before the create; not on its offline `--dry-run`). Each takes the same opt-out, ignore file and `--allow-all-ignored`, prints the same index-only lines prefixed with its own name, and adds `privateNameCheck` to `--json`. `pr open` and `pr edit-body` now hand `gh` the checked bytes on stdin (`--body-file -`) rather than the path. The shared adapter is `src/issue/privacyguard.ts`, and `GUARDED_VERBS` is the list docs/USAGE.md's guard section is tested against. Ruled out by name there, each because it writes no caller prose to a GitHub text field: `labels sync|rename` (taxonomy data), `label apply`, `classify apply`, `issue attach-sub`, `pr request-reviews|retarget|mark-ready|merge`, `pr threads resolve`, `run rerun`, `issue reconcile` (read-only), the `runner` verbs (a repository variable and runner labels) and `wc publish`, `tag cut --push` and `commit write` (git objects) (refs #363).
- **Consumer note** — new exit `4` on more verbs: a private repository named in text bound for a PUBLIC target now refuses `issue consolidate-close` (with a caller close comment), `idea file`, `pr open`, `pr edit-body`, `pr threads reply|settle`, `wake fire --comment`, `wake verify` and `release-publish`, where each used to write it. A check that cannot run (no private list, an empty one, an unreadable visibility) is exit `1` there too, so a credential that cannot list private repositories — a CI `GITHUB_TOKEN` among them — now stops these verbs unless the caller passes `--skip-private-name-check` after its own check. `wake verify`'s default dry run and `wake fire --comment`'s now read GitHub. On `pr threads`, `4` also keeps its old meanings (no such thread; the pull request is not visible): a guard refusal is the one whose `--json` carries `privateNameCheck`. `pr open` and `pr threads reply|settle` reports gain `privateNameCheck` as their last key, and `pr edit-body`'s contract grows from six fields to seven. The guard's flags are refused (exit `2`) where no caller text is written: `wake fire` without `--comment`, `consolidate-close` without a close comment, `pr threads list|resolve`. A `wake --repo-slug` that is not `owner/name` is exit `2` where the guard runs.
