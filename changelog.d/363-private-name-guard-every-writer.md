- **issue, idea, pr, wake, release** — the private-name guard #329 put on `issue file`, `issue comment` and `issue edit-body` now runs before every write of caller text to a GitHub API text field: `issue consolidate-close` (each child's `--close-comment`/`--close-comment-map` text, before the attach), `idea file` (title and body), `pr open` (title and body, before any other call), `pr edit-body` (body, after the certifying read), `pr threads reply` and `pr threads settle` (every reply body, before the walk), `wake fire` (`--comment`, before the label is touched), `wake verify` (`--now` and the two markers, before the first read) and nen's own `src/dev/release-publish.ts` (release title and notes, before the create; not on its offline `--dry-run`). Each takes the same opt-out, ignore file and `--allow-all-ignored`, prints the same index-only lines prefixed with its own name, and adds `privateNameCheck` to `--json`. `pr open` and `pr edit-body` now hand `gh` the checked bytes on stdin (`--body-file -`) rather than the path. For every guarded verb, #329's included: an internal target is now checked like a public one; a credential whose `gh api -i user` answers no `X-OAuth-Scopes` header, or one without `repo`, is refused as a list that may be partial; and an ignore file whose real path lies inside the `--repo` working tree is refused. `wake verify --now` must be an ISO-8601 instant. The shared adapter is `src/issue/privacyguard.ts`, and `GUARDED_VERBS` is held both ways to the table in docs/USAGE.md's guard section. Not guarded, out of #363's scope rather than exempt: declared taxonomy data reviewed as its own change (`labels sync` descriptions, `labels rename` names), and git objects that reach GitHub by push rather than through an API text field (commit messages from `commit write`/`wc publish`, the tag message of `tag cut --message --push`) — follow-ups: label descriptions, `tag cut --message --push`, push-side commit messages. Writers with no caller prose (`label apply`, `classify apply`, `issue attach-sub`, `pr request-reviews|retarget|mark-ready|merge`, `pr threads resolve`, `run rerun`), the read-only `issue reconcile` and the `runner` verbs (a variable and labels the public cannot read) are named there too (refs #363).
- **Consumer note** — new exit `4` on more verbs: a private repository named in text bound for a PUBLIC or INTERNAL target now refuses `issue consolidate-close` (with a caller close comment), `idea file`, `pr open`, `pr edit-body`, `pr threads reply|settle`, `wake fire --comment`, `wake verify` and `release-publish`, where each used to write it. A check that cannot run is exit `1` on every guarded verb, #329's three included, and that now covers a credential that cannot be shown to see every private repository: a fine-grained PAT, an app token or a CI `GITHUB_TOKEN` (no `X-OAuth-Scopes`), or a classic token without `repo`. Use a classic token with `repo`, or pass `--skip-private-name-check` after your own check. An internal target used to be skipped and is now checked. An ignore file inside the `--repo` checkout is now exit `2`; keep it outside the tree. `release-publish` under the declared `nen shu release` row forwards no flags and `nen shu` reports any failing step as `1`: a hit or an unprovable credential stops the release at `1` with no opt-out — run `bun src/dev/release-publish.ts` directly with `--private-names-ignore-file <path>` or `--skip-private-name-check`, or declare the ignore file in the contract argv. `wake verify`'s default dry run now also reads the target's visibility, the credential's scopes and its private-repository list; `wake fire --comment`'s dry run now reads GitHub. `wake verify --now` that is not an ISO-8601 instant is exit `2`. On `pr threads`, `4` keeps its old meanings (no such thread; the pull request is not visible): a guard refusal is told apart by `privateNameCheck.result: "refused"` under `--json`. `pr open` and `pr threads reply|settle` reports gain `privateNameCheck` as their last key, and `pr edit-body`'s contract grows from six fields to seven. The guard's flags are refused (exit `2`) where no caller text is written: `wake fire` without `--comment`, `consolidate-close` without a close comment, `pr threads list|resolve`. A `wake --repo-slug` that is not `owner/name` is exit `2` where the guard runs.
