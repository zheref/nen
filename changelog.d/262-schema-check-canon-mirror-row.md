- **schema** — `schema check` gains a `.claude/rules/` row, after `nen/decisions.json`, comparing a consumer's canon mirror as written by `nen canon mirror generate` with the bindings in `.claude/canon-values.yml`, without a canon checkout. The values each token held in earlier committed revisions (the most recent 100 that did not delete the file) are read from git, raw, through `git cat-file blob`, offline (`GIT_NO_LAZY_FETCH=1`). The row FAILs, naming the token, both values and the files, when a token's bound value is nowhere in the mirror while an earlier value of it is (`SNAPSHOT_OS is bound to '27.0' but 3 file(s) still carry '26.5': …`), or when an earlier value is a table cell or code span on a line beside the bound value or the token's name, the hardcoded-column case a drift check accepts. Each FAIL ends `Regenerate the mirror (nen canon mirror generate); never hand-edit it (CON-13).` An earlier value in prose elsewhere in a mirror that carries the bound value is not a finding, nor is a value that is any token's current binding, or a consumer's own unmarked rule. No `.claude/canon-values.yml`, or an empty `.claude/rules/`, reads `ok`. Every comparison that could not be made is a `warn` row reading `NOT CHECKED`: `.md` files none of which carries nen's marker (a mirror the older `sync-canon` wrote is not read), a shallow clone, a history or a revision git cannot read, or no committed revision (refs #262).
- **Consumer note** — `schema check --json` carries one more row, `file: ".claude/rules/"`, last before the `--ledger` row; a reader that indexes rows by position must account for it. In a repository with `.claude/canon-values.yml` and a generated mirror, `schema check` now runs `git rev-parse`, `git log` and `git cat-file`, and a stale mirror turns its exit `0` into `1` on the same bytes. A consumer whose mirror still carries the `sync-canon` marker reads `NOT CHECKED` until it regenerates with `nen canon mirror generate`.
