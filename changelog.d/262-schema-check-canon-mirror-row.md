- **schema** — `schema check` gains a `.claude/rules/` row, after `nen/decisions.json`, comparing a consumer's generated canon mirror with the bindings in `.claude/canon-values.yml` without a canon checkout. The values each token held in earlier committed revisions (the most recent 100) are read from git, raw, through `git cat-file blob`. The row FAILs, naming the token, both values and the files, when a token's bound value is nowhere in the mirror while an earlier value of it is (`SNAPSHOT_OS is bound to '27.0' but 3 file(s) still carry '26.5': …`), or when an earlier value sits on a line beside the bound value or the token's name, the hardcoded-column case a drift check accepts. Each FAIL ends `Regenerate the mirror (nen canon mirror generate); never hand-edit it (CON-13).` An earlier value elsewhere in a mirror that carries the bound value is not a finding, nor is a value that is any token's current binding, a value inside a longer literal, or a consumer's own unmarked rule. No `.claude/canon-values.yml` reads `absent (optional)`; a history git cannot read is a `warn` row reading `NOT CHECKED` (refs #262).
- **Consumer note** — `schema check --json` carries one more row, `file: ".claude/rules/"`, last before the `--ledger` row; a reader that indexes rows by position must account for it. In a repository with `.claude/canon-values.yml` and a generated mirror, `schema check` now runs `git log` and `git cat-file`, and a stale mirror turns its exit `0` into `1` on the same bytes.
