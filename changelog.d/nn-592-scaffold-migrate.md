- New verb `nen scaffold migrate --repo <path> [--dry-run] [--json]` (zheref/nen#592): for a repository scaffolded before `nen/colors.yml` and `nen/gates.json` existed, it writes each of the two that is absent from a seed that widens nothing (`colors.yml` with no category declared; `gates.json` owing one Copilot round, `review-round-only`, with a delivery carve-out whose author pattern matches no GitHub login), reads each back through the loader `schema check` uses, and never opens an existing file: a path present in any form is `kept`, the write is an exclusive create, and a second run reports every row `kept` and exits 0. A legacy `schemas/` copy is `refused` naming `scaffold init --accept-detected`, and a symlinked `nen/` is refused before anything is written. `nen/labels.json` and `nen/repos.json` are never seeded. Exits `0` nothing refused, `1` a row refused, `2` usage; `--json` is `nen.scaffold.migrate/v0.1`.
- Behaviour changes: `nen schema check` names that command, with the checked `--repo`, on the row of a missing `nen/colors.yml` (`absent (optional) -- To create it (…), run: nen scaffold migrate --repo <path>`) and a missing `nen/gates.json` (the same sentence after its "no such file" refusal); no command is named for a present-but-malformed file, a legacy-only copy, or the unseeded `labels.json`/`repos.json`. docs/USAGE.md and README.md count 175 verbs.
