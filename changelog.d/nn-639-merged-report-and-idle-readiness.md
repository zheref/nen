- `nen report data` no longer asks CON-32 about a pull request that is no longer open (zheref/nen#639). A `MERGED` or `CLOSED` row skips both the head's `readiness` check run and the in-process gate, and its `readiness` is `{ verdict: "merged", reason: "merged — not evaluated: CON-32 readiness is a statement about an open pull request", source: "state" }` (or verdict `closed`, reason `closed without merging — not evaluated: …`). A delivered PR's report used to read `not-ready: mergeable=UNKNOWN (expected MERGEABLE — CON-42/1's added predicate)`, because GitHub stops computing mergeability once a PR merges. `--objects-from` accepts `source: "state"` and refuses it on an `OPEN` row. `nen pr ready` and the gate are unchanged.
- `linked[]` now holds only real numbers. A reference is a `#<n>` whose digits start `1`–`9` and end the token, and whose `#` is not glued to a word or an `&` unless it follows an `<owner>/<name>` path. A hex colour in a PR body (`#000000`, `#123abc`), `#0` and an HTML entity (`&#39;`) are no longer read as references, while `owner/name#591/AC-1` and `Closes #591` still are; the same rule decides which PRs `nen backlog fetch` attaches to an issue. A pull request's own number is no longer among its `linked[]`. A retained `--objects-from` file that carries a `0` (or any number below 1) in `linked[]` still loads: the entry is left out and the row's `notes[]` says `linked[] carried 0, which numbers no issue or pull request; left out`. No rendering (`linked: #n`, the register's `linkedLine`) writes a number below 1, so `<owner>/<name>#0` no longer appears.
- Spend no longer counts a `readiness` phase left open across days as work. Each `phases[]` row now ends with `countedMs` and `idleWaitMs`, worked out when the report is read; the phase ledger is never written, its contract stays `nen.phase.ledger/v0.1`, and `durationMs` keeps its meaning. A closed `readiness` phase whose span with no timed step runs over 60 minutes counts only its timed steps, and the rest is its idle wait. Spend bars use `countedMs`, and such a phase's amount reads e.g. `0.0 s counted · idle wait 6612 m 07 s excluded (no timed step for over 60 m)`, with `idle: true` on its `spendPhases[]` entry (`false` on every other). Every other phase counts its whole duration however long it ran, so a long authoring phase with no timed step is never called idle.
