- `nen report data` no longer asks CON-32 about a pull request that is no longer open (zheref/nen#639). A `MERGED` or `CLOSED` row skips both the head's `readiness` check run and the in-process gate, and its `readiness` is `{ verdict: "merged", reason: "merged — not evaluated: CON-32 readiness is a statement about an open pull request", source: "state" }` (or verdict `closed`, reason `closed without merging — not evaluated: …`). A delivered PR's report used to read `not-ready: mergeable=UNKNOWN (expected MERGEABLE — CON-42/1's added predicate)`, because GitHub stops computing mergeability once a PR merges. `--objects-from` accepts `source: "state"` only on a `MERGED` or `CLOSED` row with that state's verdict, and a retained `MERGED` or `CLOSED` row carrying an older `check` or `computed` verdict, or none, now shows the state verdict, its `notes[]` naming the verdict it replaced or saying none was retained. `nen pr ready` and the gate are unchanged.
- `linked[]` now holds only real numbers. A reference is a `#<n>` where `<n>` is 1 to 9 digits starting `1`–`9` followed by no ASCII word character, and the `#` is either not preceded by an ASCII word character, `&` or `;`, or glued to exactly one `owner/name` (two `[A-Za-z0-9_.-]+` segments joined by one `/`, the first not itself preceded by `/`, an ASCII word character, `.` or `-`). A hex colour in a PR body (`#000000`, `#123abc`), `#0`, an HTML entity (`&#39;`, `&amp;#39;`), a 20-digit run, a URL fragment (`https://example.com/faq#2`) and a longer path (`/path/to/file#12`) are no longer read as references, while `acme/widget#591/AC-1` and `Closes #591` still are; the same rule decides which PRs `nen backlog fetch` attaches to an issue. Three known limits remain: a relative two-segment path such as `docs/USAGE.md#123` is read as `#123`, `other/repo#591` is read as this repository's `#591`, and a `#` straight after `;` is not read (`Fixes #1;#2` reads `#1` only). A row's own number is no longer among its `linked[]`, on the live path and in an `--objects-from` file alike. A retained `--objects-from` file that carries a `0` (or any number below 1) in `linked[]` still loads: the entry is left out and the row's `notes[]` says `linked[] carried 0, which numbers no issue or pull request; left out`. No rendering (`linked: #n`, the register's `linkedLine`) writes a number below 1, so `<owner>/<name>#0` no longer appears.
- Spend no longer counts a `readiness` phase left open across days as work. Each `phases[]` row now ends with `countedMs` and `idleWaitMs`, worked out when the report is read; the phase ledger is never written, its contract stays `nen.phase.ledger/v0.1`, and `durationMs` keeps its meaning. A closed `readiness` phase whose untimed time (its duration less its timed steps) sums to over 60 minutes counts only its timed steps, and the untimed rest is its idle wait. A duration that is not a finite number of 0 or more, on the phase or any step, leaves the phase unread (`null`, shown as `not ended`). Spend bars use `countedMs`, and such a phase's amount reads e.g. `0.0 s counted · idle wait 6612 m 07 s excluded (untimed for over 60 m)`, with `idle: true` on its `spendPhases[]` entry (`false` on every other). Every other phase counts its whole duration however long it ran, so a long authoring phase with no timed step is never called idle.
