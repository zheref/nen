- Add `nen issue body-check (--body-file <path> | --ref <CODE>#<N> --target <owner/name>) --requirements-from <catalogue.json> [--kind <kind>]`, the issue-side sibling of `nen pr body-check`: it checks one issue body against a caller-supplied issue-sections catalogue (sections with titles, optional level and content patterns, a `rows` rule with `contiguous` and `measurable`, kinds mapping to required section ids, and `vagueAdjectives`), reports every missing or empty section, unmatched content pattern, row section without a `<PREFIX>-{n}` row, non-contiguous row and row stating no number or percentage at exit 1, and lists vague adjectives as advisories. It refuses to pick a kind when several are declared and none is given. `--json` contract `nen.issue.body-check/v0.1`.
- Add `nen issue questions (--body-file <path> | --ref <CODE>#<N> --target <owner/name>)`: counts open `- OQ-{n} (<gate>): …` rows, resolved `- ~~OQ-{n}~~ → A: …` rows and `[NEEDS …]` markers, and lists `OQ-{n}` rows in neither shape as unrecognised. It counts and never decides: exit 0 whenever the body was read, 1 when the issue could not be read. `--json` contract `nen.issue.questions/v0.1`.
- `nen issue file` and `nen idea file` take `--title-file <path>`: the title read verbatim with one trailing newline stripped, refused together with `--title`, when unreadable, or when it holds a line break (zheref/nen#444). `nen idea file` takes `--dry-run`, printing the `gh issue create` argv and the stdin line in `nen issue file --dry-run`'s shape after every check, the private-name guard included, and creating nothing.
- Behaviour changes: `nen parse izanami` classifies `nen idea file` as mutating unless `--dry-run` (it was mutating on every form, having no dry-run), and `nen issue body-check` and `nen issue questions` as read-only. `nen idea file --dry-run` and `--title-file`, which answered `unknown option` (exit 2), are now accepted.
