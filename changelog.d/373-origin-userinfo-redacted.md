An origin or remote URL that nen echoes no longer carries its userinfo: the `--target` fallback's refusal when `origin` does not read as a GitHub repository (and every verb that re-raises it, such as `runner` and `pr merge --delivery`), `repo resolve`'s `origin:` line, `--json` field and refusals, `repo classify`'s unreadable-origin refusal, and the `canon` family's checkout verification (its verified origin, `--json` field and refusals) all print `https://***@host/...` (or `***@host:path`) through one helper, `redactRemoteUrl`. A token standing alone as the userinfo, which the subprocess-output redaction kept whole, is redacted too (SEC-5, refs #373).

The host a remote CONNECTS to is now read off the raw URL, never off its redacted display form: a scheme URL's authority is the run up to the first `/`, as git's ssh:// and git:// transports read it, its host follows the last `@` inside it, and the URL has NO host wherever git and curl could connect to different places -- an `@` past the authority, a `?` or `#` before the first `/`, a bracket other than one whole `[v6]` literal, a `file://` URL, a `<transport>::` remote helper -- so `https://evil.example/x@github.com:o/n`, `ssh://[evil]@github.com/o/n`, `ssh://git@[evil]@github.com/o/n` and `ssh://github.com:22#@evil/o/n` no longer pass the `canon` host check (or `canon pin --write`, `canon mirror generate`) as github.com; in scp syntax the host is git's, the text before the first `:`. A differential test runs real `git ls-remote` with a stub `GIT_SSH` and holds nen's host equal to the one git hands ssh, or null. The same reader backs `surface install`'s marketplace-source match and the release publisher's github.com check. Redaction reads the URL whole, so whitespace or a CR inside a userinfo no longer escapes it, and a surface-reported marketplace root or served path with a bare-token userinfo is redacted too (SEC-5, SEC-7, refs #373).

Follow-ups, not in this change: a query or fragment credential (`?access_token=…`, `#…`) survives redaction unless GitHub-shaped, and `parseRemoteUrl` folds it into the slug (the sibling of NN-PR-#375's `ownerNameFromRemote` fix); `parseRemoteUrl` reads `https://tok@h:abc/o/n` as `abc/o/n` and a bracketed IPv6 host as `:1]/o/n`; `redactRemoteCredentials` still keeps a colon-less userinfo in free subprocess text.
