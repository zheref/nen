nen's own `nen/workflow.json` routes `src/runner/**` to the `security` review scope (Feitan), so a runner change raises the security reviewer as NN-PR-#334 and NN-PR-#336 should have. A survey of every other `src/**` family, against one test (does it run elevated, or read, mint or copy a host credential's value?), adds three exact files and rules out the rest; `src/review/scopes.test.ts` pins both halves against the repository's own file (refs #382).

- Ruled in: `src/runner/**` (it writes the elevated host scripts that install, stop and delete runner services and mint registration tokens with `gh`, in `src/runner/script.ts`); `src/github/client.ts` (`tokenFromEnv` reads the named token variable and sends it as the Authorization token); `src/wc/worktree.ts` (`--copy-from-core` copies gitignored credential files from core into a worktree); `src/shadow/run.ts` (dev-only; it mints `GH_TOKEN` from `gh auth token` into its own process).
- Ruled out: `src/shu/**` (`requiresEnv` asserts variable names and never reads a value, and host installs never render `sudo` or `RunAs`); `src/surface/**` (no elevation, and it only redacts credentials in output); `src/seam/exec.ts` and `src/stage/**` (they redact or detect credential shapes and read no credential); `src/supply/**` (checksum verification, no credential); `src/scaffold/**` (its `token` is a `{{token}}` template placeholder); `src/canon/checkout.ts` (it expands only the variables a checkout template names into a path, never a credential by design); the families that call `gh` or `git` on gh's own stored credential without reading it (for example `backlog`, `canon`, `classify`, `dev`, `idea`, `issue`, `label`, `labels`, `repo`, `report`, `run`, `tag`, `wake`). Every other `src/**` path neither runs elevated nor reads, mints or copies a host credential's value, and is the `code` scope's alone.
- Already covered: `src/pr/**`, `src/release/**` and `src/verbs/pr_ready.ts` by path, and `src/security/secrets.ts` by `**/*secret*`.
